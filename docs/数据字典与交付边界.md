# project4 数据字典与交付边界

版本：`project4-single-organization/1`。本文按当前代码合同描述导入、存储、身份、证据、报告和任务语义。系统用于管理会计分析辅助，正式业务结论由企业授权人员复核；是否涉及质量/GxP决策须另行做用途评估。本交付没有多租户隔离、ERP自动记账、法定电子签名或管理员不可篡改存储的承诺。

## 1. 业务主键、期间与口径

| 字段 | 类型/单位 | 约束与含义 |
|---|---|---|
| 工厂 | 非空文本 | 当前模板为`中药一厂`/`中药二厂`；企业新编码须先映射并修改受控合同 |
| 产品名称 | 非空文本 | 产品主数据名称；权限按精确名称，不能靠上传者自报角色放行 |
| 产品规格 | 非空文本 | 成本口径的一部分，不能混合不同规格后比较单位成本 |
| 月份 | `YYYY-MM` | 自然月业务期间，月份01–12；不是上传时间 |
| 原材料名称 | 非空文本 | 材料明细的附加主键；目前不是企业物料编码 |
| 费用类别 | 非空文本 | 制造费用明细的附加主键；目前不是完整成本中心/科目表 |

汇总、预算、人工的行主键为`工厂 × 产品名称 × 产品规格 × 月份`；材料明细再加`原材料名称`，制费明细再加`费用类别`。同批次主键重复会拒绝；修改已有业务主键是历史修订，不自动覆盖旧确认版本。实际输入/报告范围由应用服务按已认证角色与工厂/产品权限收窄。

源资料时间、业务有效日期、确认时间、生成时间分别保存。知识有效区间是包含起止日的日期区间，`effective_to=null` 表示未指定终止日；`known_at` 用带时区的确认时间限制历史可知资料，不用文件mtime判定知识版本有效性。

输入列中的“元”与“盒”是本次模板单位：本交付按同一币种人民币、统一费用归集/税口径后的数据分析。数据结构未提供币种/汇率/税额/物理计量单位字段，不能把混合口径文件直接导入后由模型猜测换算。由业务负责人在导入批次工单写清以下口径：生产量或完工入库量、包含/排除的税、在制品、委外、返工报废、固定/变动费用与分配基数、跨期计提、标准与实际成本、预算批次。多币种、不同规格包装量、退料冲销负数与ERP凭证映射属于后续合同扩展；当前负值校验不适用于全部真实财务凭证。

## 2. 成本导入表

每张表均包含第1节四个公共主键字段。上传格式为 CSV/XLSX；旧 XLS 需另存。CSV按 UTF-8 BOM/GB18030读取，XLSX逐工作表解析。单文件上限20 MiB、每表行数上限100000；企业部署还受代理和Streamlit上限限制。解析/校验失败保留拒绝结果，不进入确认修订。

| 表族 | 数值字段（原始列名） | 含义 |
|---|---|---|
| 成本汇总 | `产量(盒)` | 同期间同规格产量 |
| 成本汇总 | `直接材料(元/盒)`、`直接人工(元/盒)`、`制造费用(元/盒)` | 单位产品三要素成本，不是三要素总金额 |
| 成本汇总 | `单位成本(元/盒)`、`总成本(元)` | 三要素单位合计与总额 |
| 预算 | `预算产量(盒)`、`预算直接材料(元/盒)`、`预算直接人工(元/盒)`、`预算制造费用(元/盒)`、`预算单位成本(元/盒)`、`预算总成本(元)` | 与实际口径对应的预算；当前输入模板没有独立`budget_version`列，预算随成本修订快照冻结 |
| 材料明细 | `产量(盒)`、`单位消耗成本(元/盒)`、`原材料总成本(元)`、`占总材料成本比例` | 按`原材料名称`拆分的单位费用/总额；**不是采购单价或实物耗用量** |
| 人工明细 | `产量(盒)`、`直接人工总额(元)`、`总工时(小时)`、`生产人数(人)`、`工作天数(天)` | 工时/人数/天数统计；不得仅凭汇总字段推断具体员工效率或加班事件 |
| 制费明细 | `产量(盒)`、`单位费用(元/盒)`、`费用总额(元)` | 按`费用类别`拆分的单位费用/总额 |

材料比例可用百分号文本；不带百分号且0–1之间会转成百分数。校验要求每行比例0–100，分组比例和与100相差不超过1个百分点。

关键勾稽：三要素单位和与单位成本差不超过0.005元/盒；单位成本×产量与汇总总额差不超过0.01元；各明细分组总额与对应三要素单位×产量差不超过0.01元，明细产量须与汇总一致。预算执行对应闭合校验。资料缺失与数值不闭合分别列warnings/errors，不能把warning当成已补齐。

当前受控导入先读取数值字符串，用Decimal验证有限、非负、最多6位小数、数值不超过`10^12`，并检查转float后的十进制往返一致性，之后兼容现有DataFrame/JSON层。它不能修复Excel写入前已丢失的精度，也不等于整个数据管道改为任意精度定点账本。展示一般保留2位，显示舍入不能回填原值。生产口径要约定源精度、期间聚合和舍入节点，并以授权样本独立复算。

遗留内部键`cost25/cost26/erchang25/erchang26/budget/material/labor/mfg`是兼容算法/页面的表集合名称，不是通用ERP账套。跨年扩展须验证导入分桶、同比、连续期间与报告算法，不承诺任意年度财务核算。

## 3. 指标、缺口与模型解释

| 指标/概念 | 合同 |
|---|---|
| 要素金额 | 要素单位成本 × 对应产量 |
| 总额变动 | 本期总成本 − 对比期总成本 |
| 金额贡献度 | 要素金额变动 ÷ 总额变动 × 100%；总变动为0时无定义，反向因素可为负或超过100% |
| 产量/单位成本分解 | 使用确定性公式区分数量与单位成本影响，产量下降带来支出下降不等于可兑现节约 |
| 季度单位成本 | 完整期间总额 ÷ 完整期间产量；不能简单平均各月单位成本 |
| 环比 | 连续上月/上期，缺月不能用“最近有数据月”冒充 |
| 同比 | 对应去年期间；无资料时标不可用 |
| 跨厂对标 | 同产品/规格/期间和会计口径的差异及标准化比较；单位差×产量仅是比较量，不能自动作为已节约额 |
| 市场行情 | 外部参考，不能证明本期实际采购单价/领用量或具体经营事件 |
| 模型归因 | 按schema/范围/证据ID约束的解释或待核查假设；引用存在不等于语义已经被证明 |

月度、季度、专题报告使用同一冻结payload分别生成DOCX/PDF。正式期间需要相应月份汇总及经营明细完整；核查稿保留缺口且不能签发为正式报告。二厂对标、预算、市场或历史对照缺少时使用实际可用性标记，不能制造占位资料。只通过格式/占位符检查不能证明成本计算和因果解释均正确。

`claim_type/kind`等证据语义区分数据事实、文档依据、待核查假设。文档只支持机制说明，未经当期凭证/设备/批次记录核对，不得认定其描述在当期实际发生。模型缺失、超时、拒答、权限过滤后无证据与完整成功需要在页面/报告中分别显示。

## 4. 来源定位与版本标识

| 字段 | 含义与限制 |
|---|---|
| `_source_file` / `source.file` | 原始文件名称/来源定位；路径不是授权依据 |
| `_source_hash` / `source.sha256` | 原件字节的完整SHA256；传统审计库的短hash字段不替代完整hash |
| `_source_sheet` / `sheet` | XLSX工作表名或CSV标识 |
| `_source_row` / `record_number` | 含表头的导入记录序号；多行CSV单元格时不等于物理行号 |
| `page` / `offset` / `ordinal` | 仅在解析器实际提供时填写，分别表示页/正文偏移/切片序号，不伪造bounding box |
| `revision`、`base_hash` | 成本确认修订号与预览所基于的数据hash，防止陈旧预览覆盖 |
| `doc_id/version_id/version` | 逻辑知识文档、不可变版本ID、该文档版本序号 |
| `index_release_id` | 检索发布的文档版本集合及解析/chunker/模型/索引产物manifest |
| `analysis_run_id/report_id` | 当次分析/报告运行身份；新运行不得冒充历史原件 |
| `frozen_hash`、`payload hash` | 冻结内容校验值；不是管理员不可重算的签名 |
| `task_id/version/idempotency_key` | 任务业务身份、批准版本及外发幂等身份，重试不生成新task_id |

确认修订是“预览与确认两步业务流程 + 单数据库事务 + 乐观并发 + 内容校验”，不是跨SQLite/索引的分布式两阶段提交，也没有跨修订哈希链。内容Blob可按hash去重，同正文的范围/有效期/业务metadata变化仍应形成独立业务版本；存储去重不等于审批去重。

## 5. SQLite与文件数据字典

所有下列受控库位于 `COST_MANAGED_DIR`；兼容索引、原始源表/行情/模板/文件产物位于 `COST_DATA_DIR`。SQL列中的JSON使用文本保存，业务字段访问须经应用权限控制，不能把目录路径隔离当成多租户后端。

| 存储 | 主表/对象 | 权威内容与恢复重点 |
|---|---|---|
| `cost_versions.db` | `revisions(id,created,actor,reason,hash,data,changes)` | 每次确认的全表集合和变更；触发器拒绝修改/删除确认修订 |
| 同上 | `stages(id,created,actor,base_hash,payload,status)` | 预览与校验结果，基线hash用于并发检查；不是已生效数据 |
| 同上 | `source_files(hash,name,content)` | CSV/XLSX原件BLOB；按完整hash验证 |
| 同上 | `events` | 导入/拒绝/确认事件、业务期间、操作者与明细 |
| `knowledge.db` | `documents(doc_id,title,head_version,created_at,created_by)` | 逻辑文档身份与当前头版本 |
| 同上 | `versions` | 文件/正文hash、正文/解析器、产品/工厂范围、visibility、业务有效期、确认时点/人/原因、业务metadata；版本只追加 |
| 同上 | `stages`、`events` | 待确认内容/基线/payload hash和变更历史 |
| `blobs/<sha256>` | 原件文件 | 已登记PDF/DOCX/TXT/CSV原件，可多个合法版本共享相同字节 |
| `knowledge_releases.db` | `releases`、`active_release`、`revocations` | building/published/failed、manifest/hash、活动指针和撤销；确认文档不代表已发布检索 |
| `knowledge_releases/<release_id>/index.sqlite` | `generation`、`chunks`、`graph_edges` | 统一发布的切片、metadata、词法/向量/图关系；代际须与manifest一致 |
| `knowledge_releases.db.releases.manifest/manifest_sha256` | canonical发布清单/hash | 原文版本集合、解析/切片/模型指纹、索引字节hash；清单仅以数据库为权威，不要求旁侧JSON，备份保持索引原字节 |
| `snapshots.db` | `snapshots(id,created,product,month,actor,hash,payload)` | 历史分析、输入表、原件副本/引用、代码/行情hash；读取先校验、不调用模型 |
| `reports.db` | `reports` | 冻结报告payload/hash、组织/工厂/产品、创建者、审批状态与版本 |
| 同上 | `report_events`、`report_artifacts` | 审批事件、按报告/格式/审批版本保存的DOCX/PDF字节及hash；必须随库备份 |
| `periods.db` | `periods(factory,product,month,state,version,actor,reason,updated)` | open/closed；当前期间锁按工厂/产品/月，不另按规格分锁 |
| 同上 | `period_events` | 关账/重开原因与版本的追加事件 |
| `task_workflow.db` | `tasks` | 当前草稿/批准内容摘要、范围、主体、批准/下发/完成状态和回执摘要 |
| 同上 | `task_versions` | 逐版本不可变任务内容、hash和生成信息 |
| 同上 | `outbox` | 同事务创建的批准外发事件，稳定幂等键、payload hash、尝试数、租约、未知态和下次尝试时点 |
| 同上 | `task_events`、`task_receipts` | 追加任务动作和远端回执，恢复后不能丢弃核对依据 |
| 兼容 `kb_audit.db` | `audit_log` | 旧上传/索引审计，包含操作时间、filename、operator、scope、counts、status；时间/短hash语义与新库不同 |
| `outputs/artifacts`、模板与上传目录 | 文件 | 报告下载、已授权模板和来源文件；数据根目录规则见运维手册 |
| `.operations.lock/.maintenance.json` | 运维协调 | 跨进程排他锁与维护门禁；锁不是数据库备份内容 |

应用层追加约束、SQL触发器、内容hash支持追溯和误改检测，但有主机/数据库/备份控制权限的管理员仍能修改文件或重算hash。更强的保留锁、外部签名锚点、职责分离和特权审计须由目标企业体系提供。

## 6. 身份、角色与数据范围

Principal包含稳定`user_id`、显示名、roles、factories、products、`tenant_id=default`及认证来源。OIDC主体由可信签发者+subject确定，授权从服务端JSON读取，不从上传字段、HTTP正文、姓名输入或模型输出生成权限。

| 角色 | 当前主要职责 |
|---|---|
| analyst | 看板/数据读取与预览、知识读取、分析/报告草稿、任务草稿与读取 |
| supervisor | 数据确认/期间管理、报告提交复核、任务批准/下发/审计，按范围读知识与业务数据 |
| knowledge_admin | 知识预览、确认发布与知识审计，按被授范围管理 |
| auditor | 授权范围内业务与知识/报告/任务审计只读 |
| system_admin | 系统状态、备份、配置；不隐含业务全域可读 |

`visibility=public` 表示**本组织范围内明确公共的知识**，并非互联网公开。`scoped` 需要声明且满足工厂/产品范围，`unknown` 不能自动变公共。旧资料缺少scope必须经迁移/重新确认。撤权和知识撤销须先在允许集合阻断，再处理缓存或索引清理；旧报告/快照引用也不能绕过当前读权限。

CLI备份/恢复是OS管理员操作，操作系统能读整个数据卷的权限大于业务角色；它们不暴露成无认证HTTP接口。`review-complete --actor`是运维交接记录，可信程度依赖该OS账户与工单制度，不是由自由输入就获得业务角色。

## 7. 报告与任务状态语义

报告保存固定内容后经过draft → submitted → approved/rejected，企业模式由另一位主管审批，审批意见/版本保留。正式报告须满足资料完整性；有缺口的核查稿不因点击批准而变成完整正式报告。导出文件标明草稿/签发、报告ID、审批版本和审核记录。签发文本不是法定密码学电子签名。

任务采用草稿、确认/批准、明确下发、outbox、远端回执的独立层次；UI一次生成不应同时外发。outbox常见状态如下：

| 状态 | 含义/恢复处置 |
|---|---|
| blocked | 批准记录已存但未获得实际下发条件；恢复后仍需核对 |
| pending/retry | 待发/有限重试；恢复后先查询远端，禁止无条件重发 |
| leased | 某次派发占有租约；恢复时不能假定该次未产生外部效果 |
| unknown | 超时或回执不完整，发送结果不确定，需查询/人工核对 |
| delivered | 远端任务服务已受理且回执匹配，不等于微信真实送达或业务已完成 |
| failed/cancelled | 按业务/传输规则失败或取消；仍保留版本、事件与回执 |

官方mock的创建任务接口自身产生一次模拟通知，不额外无条件调用notify。固定task_id重试前先GET核对；mock重启遗失远端内存也不代表之前已受理任务应重发。真实RPA的网络目标/合同和通知效果必须另行接入验收，mock闭环不能宣传成真实企业整改完成。

备份恢复后新增全局 `needs_review` 核对门禁，保留原SQL状态枚举；派发入口检查门禁，GET同步仍可用于核对。门禁清除不自动调度、不修改批准内容，也不代替业务重新下发判断。

## 8. 可交付范围与现场待验收项

代码交付包括确定性成本计算、受控导入/期间、知识版本/发布、共享身份授权、冻结报告与DOCX/PDF、任务版本/outbox及mock适配、单实例部署配置、预检与隔离备份恢复实现。历史回看使用已保存字节/内容；数值复算需要同输入/规则/版本；模型重跑是新运行，不保证文字逐字相同。
