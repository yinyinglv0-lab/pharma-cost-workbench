# 第二轮核查实施与运行说明

## 状态与适用范围

本文保留第二轮制造业配置化接入的**底层流程**，不是全链路验收报告。2026-09-24起已从评委主导航移除制造业页面，保留受权限保护的服务/API和页面源码；下文页面步骤是保留代码的操作参考，不表示主界面仍有入口。历史五行业实证及边界见 `docs/跨行业迁移与边界.md`。五组行业样例仅用于离线 SIMULATION，人工独立质量评分仍待填写，第三机部署尚未完成。本轮未执行容器构建，不在主任务 GO 前生成或覆盖最终交付包；本文不给出滚动测试总数或“端到端全部通过”结论。

新服务名为 `enterprise/manufacturing_service.py`。旧制药默认领域、三种原产品、原成本库、历史报告及已冻结 graph V3 不由新制造业配置自动替换。工作台专注原有制药页面；“制造业配置与分析”页面源码只作为受控集成参考保留，不再注册主导航，也未新增可绕过认证的直接访问方式。新制造业运行要求 `manufacturing-domain/2` + `manufacturing-adapter/2`；旧 /1 适配器及四份未激活模板仍保留自身契约。

## 1. 运维准备与身份边界

1. 按已有部署手册准备 Python 依赖、托管目录及原有认证模式；本说明不提供身份绕过或生产账号。
2. 数据管理员先确认币种、产量分母、精度、工厂/产品/规格、期间、源文件出处与权限。配置由有权运维审核后安装，不能将用户提示词、模型输出或任意浏览器字典作为权限策略。
3. 安装配置需 `system.configure`，且操作者须有配置内**全部**工厂/产品的数据读取范围。暂存、确认、知识管理、分析、报告读取和任务创建各受原有独立动作权限约束。
4. 安装/更改配置不会授予访问权限、切换旧默认领域或批准模型/RPA；不在配置中写 endpoint、密钥、执行表达式、路径加载器或权限覆盖。
5. 实际企业配置和实际 CSV 放在受控业务通道，不修改公开模拟目录冒充可公开分发内容。源码包不是包含企业数据、索引、模型权重的完整运行备份。

## 2. 安装领域与适配器

受权集成人员通过下列API安装领域 JSON 与适配器 JSON 原文，填预期当前配置版本（首次为 `0`）及理由。保留页面代码同样调用 `ManufacturingRepository.install_profile()`，但当前主导航不展示该页。API仍执行相同权限检查：

```text
POST /api/manufacturing/profiles
{
  "profile_json": "<经过运维审核的领域JSON原文>",
  "adapter_json": "<经过运维审核的适配器JSON原文>",
  "expected_version": 0,
  "reason": "本次安装的核对依据"
}
```

这里两份 JSON 是字符串字段，不是未经严格解析的对象。重复键、未知字段、NaN/Infinity、schema 降级或绑定不一致必须拒绝。API 不接受附加 actor、root 或路径字段。

领域应显式声明：行业与版本、数据分类、home/peer 工厂、产品 ID/名称/规格/类别/分母、材料及材料单位、BOM 参考用量、工序/设备关系、指标名/单位/方向/固定计算种类、限制说明。BOM 是参考语义，不是实际领料数据。适配器显式映射源列、工厂、产品/规格、币种与有限换算；恒等换算也须明确。

公开样例路径为 `config/manufacturing_examples/{pharma,machinery,auto_parts,chemicals,electronics}/`，每组有 `domain.json`、`adapter.json`、五张 CSV、`knowledge.txt`、`manifest.json`。`manifest.json` 是说明性文件清单，不是自动装载器；安装配置不会自动导入 CSV 或知识。

- 制药样例是 SIMULATION 第四/第五种片剂，分母 `tablet`，不是现有三产品的盒数转换。
- 化工样例分母 `kg`；机械、汽车零部件、电子样例分母 `piece`。
- 各组均为 CNY，明确恒等因子；全部身份、量价、参考区间和工艺设备语义是模拟，不是实际部署记录。

## 3. 五类 CSV 的完整输入

第二步必须同时上传 `actual`、`budget`、`materials`、`labor`、`overhead`。输入 UTF-8，每文件不超过 20 MiB、合计不超过 60 MiB。API 的 `periods_json` 提供明确、顺序唯一、连续的月份数组；当前 HTTP 入口限制一至 120 个月。不能用空表替代缺失表或让服务猜测月份。

当前公开样例的精确表头如下。`actual` 与 `budget` 的源列名可由适配器显式映射；明细字段使用下面的固定合同。表头可以重新排序，但重复、缺失、额外列会拒绝。

```csv
factory,product,specification,month,material,labor,overhead,unitcost,output,total,currency,quantity_unit,cost_denominator_unit
```

```csv
factory,product,specification,month,material_id,unitcost,amount,currency,reporting_unit,quantity,quantity_unit,unit_price
```

```csv
factory,product,specification,month,amount,currency,reporting_unit,hours,headcount,working_days,hourly_rate
```

```csv
factory,product,specification,month,category,unitcost,amount,currency,reporting_unit
```

依次对应实际/预算、材料、人工、制造费用。成本数值是原始十进制字符串，不先转 float；产量为正且成本非负。实际与预算覆盖**全部配置产品/规格 × 两个配置工厂 × 全部声明月份**；每条实际观察都有材料、人工、制造费用明细，材料行覆盖其显式 BOM。当前不支持上传“只改本月某行”的补丁；应在受控上游整理完整快照后再提交，不隐式合并。

校验包括：单位/币种绑定、唯一观察身份、三要素之和、单位成本乘产量、各明细与对应实际要素总额精确闭合。源会计口径若因展示精度不闭合，应取得确认后的准确原始值，不能让系统自动补差。

### 缺失实际量价不能从参考资料补齐

材料 `quantity / quantity_unit / unit_price` 与人工 `hours / headcount / working_days / hourly_rate` 的允许缺项使用空单元格。空白不等于零。数量和单位需同时提供；有价格与数量时须精确核对金额，提供时薪则需实际工时并核对乘积。不得使用 BOM、市场价、金额除价格、人数乘天数来伪造实际消耗或工时。

模拟样例的第二条材料行特意留空数量、数量单位和采购单价，用于验证“不可用”而不是自动插补。`source_only` 指标（如良率）未给出实际观察时保持不可用，不能从成本、产量或知识参考区间推导。

## 4. 暂存、确认与读取

点击“校验并暂存五表快照”，核对每表行数、源摘要、配置摘要、月份与基础版本。此时状态 `staged_not_active`，不是有效数据。确认人勾选核对并填理由后，显式点击确认；不同用户或并发上传造成期望版本不匹配时拒绝，不覆写已有版本。

仓库独立保存原始 CSV 字节和 SHA-256，并在确认/读取时从这些原字节重建表、核对冻结配置和运行指纹。不是相信客户端随意提供的 `source_sha256`。配置变更后旧数据不能自动混用，要按新配置重新暂存确认。

| 方法与路径 | 输入/作用 |
| --- | --- |
| `GET /api/manufacturing/profiles` | 只列当前身份可读取完整范围的配置 |
| `POST /api/manufacturing/profiles/{profile_id}/stage` | multipart 五文件、`periods_json`、规范非负整数文本 `expected_revision` |
| `POST /api/manufacturing/stages/{stage_id}/confirm` | JSON `expected_revision`、`reason` |
| `GET /api/manufacturing/profiles/{profile_id}/current` | 已确认版本、范围、摘要，不返回内部 runtime 对象 |

原始字节摘要证明一致性，不自动证明真实世界来源或企业业务授权。新仓库存储与旧制药成本快照分开，不覆写 `costs.db`。

## 5. 知识原文接入：三道不同操作

第三步选择文件、标题、配置产品 ID、类别、生效/失效日期及审核理由。产品、规格、工厂、领域配置指纹和词表由服务端绑定。生产工艺、配方、设备类每次只登记一个产品；文档必须真的适用于所选范围，不能借范围标签把混合产品段落变成适用证据。

1. **暂存预览**：`POST /api/manufacturing/profiles/{profile_id}/knowledge/stage`；返回未发布的 stage。
2. **核对并确认知识版本**：`POST /api/manufacturing/profiles/{profile_id}/knowledge/confirm`，提供 `stage_id` 与理由。配置变化使旧暂存无效。确认只进入目录，返回 `catalog_only` / `index_publication_required: true`。
3. **受控混合发布**：转到既有知识文档库，按已有知识发布流程构建/核对并发布 dense + BM25 等受控索引；新制造业页不自动发布。正式模型分析要求未降级的已发布混合检索，不用仅关键词或缺失向量的状态冒充成功；确定性分析仍可在明确标记检索降级、正式模型被阻止的状态下冻结。

配置词表不是证据本身；原文中的关系、值与可定位片段仍是图谱和引用的依据。词表及其指纹随新 V4 发布冻结，历史 graph V3 继续用自身冻结内容，不能因当前领域变动而重新解释旧发布。BGE 权重由既有受控离线运维提供，源码 ZIP 和 Docker COPY 不携带本地权重。

### 通用参考 CSV（独立于五张成本表）

市场参考：

```csv
material,grade,unit,month,price,source_market
```

行业参考：

```csv
category,metric,unit,period_start,period_end,p25,p50,p75,source_name
```

它们通过知识文件流程进入，不是第六、第七张成本导入表。材料/类别/指标必须匹配冻结领域语义，月份/有效期、单位和数值顺序须校验；百分数 `62` 表示 62%，不是 0.62。市场参考不是实际采购价；行业分位数必须有真实来源与可比口径。公开模拟知识中的虚构参考区间不得当真实行业数据使用。

## 6. 预览、模型与冻结分析

第四步读取已确认快照，选择精确产品/规格/月：

- “仅预览确定性计算”调用 `POST /api/manufacturing/profiles/{profile_id}/preview`，不调用生成模型，不写分析记录，不建任务。
- “生成并冻结本次分析”调用 `POST /api/manufacturing/profiles/{profile_id}/analyze`。JSON 为 `product`、`specification`、`month` 和严格布尔 `use_llm`（默认 `false`）。这一步保存独立分析记录，不能把它描述成纯只读预览。
- **启用模型是单独、显式的批准动作**。页面勾选不代替服务端模型/云端数据授权；仍遵守原有任务路由、端点出站门禁、超时与并发限制。当前网关温度固定 `0.1`、JSON 响应。没有批准时保持关闭，不读业务 JSON 中的模型配置。
- 模型前需正式受控混合检索；降级或发布不可用时不调用正式模型。模型返回还须通过共享 `analysis_contract` 的输出、证据、数值和责任动作校验；失败可保留确定性结果与明确状态，不能写成模型已成功生成。
- 新数据投影保留原工厂和 CNY/kg、CNY/piece、CNY/tablet 等计量，不把新行业换名成制药数据。程序负责数值与精确桥接；共享叙述区分观察、机制依据、待核查假设、行动和缺证项。

分析前后均检查数据/配置版本，保存时检查知识访问。页面和 `GET /api/manufacturing/runs/{run_id}` 读取冻结结果时重新授权；可下载冻结分析 JSON，包含数据/配置/分析摘要、引用、模型与检索回执、源码/部署指纹和待人工复核状态。

**导出边界**：制造业页除冻结 JSON 外，可显式“准备Word与PDF阅读副本”，调用 `ManufacturingService.export_report()`；API 为 `GET /api/manufacturing/runs/{run_id}/export/docx` 或 `/pdf`。新 `enterprise/manufacturing_report.py` 从同一冻结快照生成可编辑 DOCX 与可检索 PDF，渲染前后均通过 `get_run()` 重新授权，不调用模型、不重取数据。它们是 `needs_human_review` 的未签发阅读稿，JSON 仍是审计依据；缺失受控字体时明确失败。旧 `report/narrative_adapter.py` 仍负责旧制药完整期间叙述，不据此声称旧模板所有流程已通用化。

新受控散文合同 `bound-numeric-prose/1` 由服务端标记启用：模型可原样采用要素内完整绑定事实句，但不能拆取数值改换主体/期间/单位或自行计算；内部 JSON 传输、旧合同、因果/证据/行动门控及最多一次受预算修正保留。页面只呈现已校验散文，确定性字段留作审计。公开合同、导出与尚待真实一致性验收的细节见 `docs/受控散文生成与阅读导出.md`。

## 7. 草稿与实际发送分开

第五步选归因或对标及成本要素，显式创建任务草稿：

```text
POST /api/manufacturing/runs/{run_id}/task-draft
{"kind": "attribution", "element": "材料"}
```

草稿绑定冻结分析 ID/摘要、证据 ID/摘要与产品/期间。页面不会自动填成已批准状态；返回 `approved: false`、`sent: false`。无待核查差异的要素不应创建整改任务。

转入既有整改任务页补齐负责人、期限和可执行计划，再按权限分别提交、批准、签发；固定版本 outbox、幂等、受限 RPA 地址、回执核对与审计仍走原链条。没有制造业自动发送端点。mock/loopback 只证明模拟路径，不是向真实业务系统发送的验收；不得把此页的模型批准当作任务发送批准。

## 8. 源码分发、不可变旧包与离线核查

`scripts/build_source_bundle.py` 的 `CORE_TREES`、测试路径和公开文档均为字面清单。所有 45 个模拟文件逐个读审后冻结原始字节 SHA-256，统一声明 SIMULATION / 非真实数据集。`REVIEWED_CONFIG_HASHES` 的旧值和语义审查方式不变。新文件、改动后的样例或客户配置不能凭目录/schema 自动获准；普通密钥/路径扫描仍执行。

部署指纹显式覆盖 45 个样例、README 与本轮公开说明，不扫描任意客户配置。Docker 上下文维持默认拒绝，25 个样例 CSV 是逐路径例外，构建代码会核对 45 个样例摘要；不拷贝数据库、真实 CSV、秘密或本地权重。这里只描述构建规则，**本轮没有执行容器构建或启动服务器**。
