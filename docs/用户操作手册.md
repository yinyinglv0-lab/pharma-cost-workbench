# 制药成本分析工作台用户操作手册

本手册依据当前正式 Streamlit 入口 `enterprise_app.py`、全部 `app_pages/*.py`、`report_web.py`、`dashboard_web.py` 及服务端权限实现编写。菜单、按钮和提示以当前源码中的文字为准；页面是否出现、记录是否可见，还取决于登录角色及工厂、产品授权范围。

本文说明操作方法与结果判读，不记录测试通过率或验收结论。它不证明真实模型调用、生产 OIDC、端到端操作、视频录制或评测已通过，也不证明真实微信送达。实际验证结果应以单独的验收记录为准。

## 1. 进入系统与核对身份

由部署人员提供已运行的正式工作台地址，打开后核对侧栏的“制药成本分析工作台”“当前用户”和“角色”。正式多页导航由 `enterprise_app.py` 中的 `st.navigation` 提供；本手册不以旧的独立页面或后台入口代替正式工作台。

### 1.1 local 本机演示

- 侧栏显示“本机演示 · 服务端 OS 身份 · 全角色”，并提示“仅限回环访问；本机审批为模拟审批”。系统使用运行服务的当前 OS 用户身份，无需在业务页面输入用户名、密码、角色或审批人。
- local 仅用于本机回环访问。出现“本机模式必须绑定127.0.0.1；网络部署请配置OIDC身份认证。”或“本机模式拒绝非本机访问。”时，请交部署人员处理；不要把 local 当作网络部署的登录方式。
- 同一 OS 身份可以演示提交、主管审核、签发等步骤。页面中的“模拟独立主管审批”只说明演示例外，不能据此认定已经完成真实的双人复核。

### 1.2 企业 OIDC 登录

1. 企业模式未登录时，页面显示“请使用企业账户登录。”，点击“企业账户登录”，按企业身份提供方的流程完成认证。
2. 返回后核对当前用户和角色。服务端通过已验证身份的 subject 查找角色、组织、工厂和产品授权映射；未授权、停用、签发者不匹配或组织不匹配的账户会被拒绝。
3. 出现“登录已过期，请重新登录。”时，点击“重新登录”退出过期会话，再按企业账户登录流程进入。正常离开可点击侧栏“退出登录”。
4. 菜单缺失或出现无权访问提示时，联系授权管理员核对账户映射。不能靠修改页面输入、URL、责任人姓名或任务 JSON 获取权限，也不能回退到本机身份绕过企业认证。

企业 OIDC 需要部署人员完成身份提供方、Streamlit 登录及服务端授权映射配置。本手册只说明现有入口和限制，不代表这些配置在目标生产环境已验收。

### 1.3 角色与业务职责

下表列出单一角色的主要页面能力。一个账户可以有多个角色；无论角色多少，业务操作仍受组织、工厂和产品范围约束。

| 角色代码 | 主要职责与可操作范围 |
| --- | --- |
| `analyst` | 查看授权数据和知识，上传成本并生成预览，生成归因和报告，查看报告、创建及提交任务草稿；不能确认成本生效、批准报告或签发发送任务。 |
| `supervisor` | 查看并分析业务数据，确认成本、关账/重开，发布已有确认知识版本的索引，生成及审核报告，审核、签发、发送和查询任务，查看相关审计。仅此角色没有知识原件登记预览权限。 |
| `knowledge_admin` | 登记知识原件、生成差异、确认知识版本、发布索引、查看知识操作记录。仅此角色不获得成本分析、报告或任务权限。组织公开资料还要求全部工厂和产品范围。 |
| `auditor` | 查看授权成本、看板、知识、报告、任务及相关审计；不能生成分析、提交成本、批准或发送任务。“查询官方 mock 回执”也要求发送权限，审计角色可查看已有回执。 |
| `system_admin` | 进入系统设置，配置模型并执行连通检查；仅此角色不获得业务数据、报告或任务权限，页面也不提供自由修改账户授权的表单。 |

“责任人姓名”“责任部门”“责任岗位”是任务的业务分配信息；“适用工厂”“适用产品”是知识的业务元数据。它们都不是登录身份或权限配置。实际操作人、审批人、签发人由服务端记录。身份或范围变化后，系统会清除会话中的旧记录、下载状态和表单状态，并重新验权。

## 2. 正式导航与推荐操作顺序

### 2.1 菜单与页内标题对照

| 侧栏分组 | 实际菜单标签 | 打开后的主标题 |
| --- | --- | --- |
| 工作台 | 工作总览 | 成本分析工作台 |
| 资料与数据 | 知识文档库 | 知识文档与版本 |
| 资料与数据 | 月度数据管理 | 月度数据管理 |
| 成本分析 | 模块一 · 智能报告 | 成本智能报告 |
| 成本分析 | 模块二 · 产品成本 | 产品成本分析 |
| 成本分析 | 模块三 · 对标分析 | 跨厂成本对标 |
| 成本分析 | 模块四 · 整改任务 | 整改任务与跟踪 |
| 追溯与运行 | 分析档案与更新记录 | 分析档案与更新追溯 |
| 追溯与运行 | 系统设置与运行检查 | 系统设置与运行检查 |

“工作总览”根据权限提供“月度数据”“知识文档”“产品分析”“报告与审核”“整改任务”“系统设置”快捷入口。可以在“业务月份”中选择月份，查看“当期产品数据”“最新知识版本”和“最近分析档案”。“当前成本数据版本”显示赛题原始数据基线或已生效的版本号，不代表已经完成某项验收。

### 2.2 一次业务处理的顺序

1. 在“月度数据管理”上传文件、校验预览，由主管确认生效；历史修订先检查期间是否关账。
2. 在“知识文档库”核对已有资料，必要时登记、确认版本并单独发布索引。
3. 在“模块二 · 产品成本”查看同口径图表和归因，在“模块三 · 对标分析”比较两厂同产品、同规格、同月份记录。
4. 在“模块一 · 智能报告”生成冻结草稿、检查证据与期间完整性、提交主管审核，再准备和下载对应状态的 Word/PDF。
5. 在“模块四 · 整改任务”补全责任分配、保存、提交、批准、签发，之后才可发送到官方 mock 并查询回执。
6. 分别在分析档案、报告审核记录、任务审计和知识版本记录中追溯结果。

各步骤的成功提示只说明相应动作完成。例如成本“校验并预览”不等于“确认生效”；知识“确认登记此版本”不等于“构建并发布索引”；任务“批准任务”不等于“签发批准版本”或 mock 已受理。

## 3. 月度数据上传、预览与确认

### 3.1 准备文件

进入“月度数据管理”，展开“下载数据模板与导入说明”。支持 CSV 和 XLSX 多工作表，可把汇总与相关明细作为多文件整批提交。单文件应非空且不超过 20MB；旧版 XLS 需另存为 XLSX。

| 下载按钮 | 用途及主要数值字段 |
| --- | --- |
| 下载cost模板 | 成本汇总：产量、直接材料、直接人工、制造费用、单位成本、总成本。 |
| 下载budget模板 | 预算产量、预算三要素单位成本、预算单位成本和预算总成本。 |
| 下载material模板 | 材料明细：原材料名称、产量、单位消耗成本、原材料总成本、占总材料成本比例。 |
| 下载labor模板 | 人工明细：产量、直接人工总额、总工时、生产人数、工作天数。 |
| 下载mfg模板 | 制造费用明细：费用类别、产量、单位费用、费用总额。 |

保留模板的完整列名和单位。所有表都需填写“工厂”“产品名称”“产品规格”“月份”；材料明细还按原材料名称区分，制造费用明细还按费用类别区分。工厂使用“中药一厂”或“中药二厂”，月份使用 `YYYY-MM`，同批次主键不能重复。金额和产量等数值必须符合模板合同，不能用空值、负数或无限值代替数据。

上传前核对三要素之和与单位成本、单位成本乘产量与总成本、明细与汇总金额及产量的一致性。建议把相互依赖的汇总和明细一起提交，以便统一校验。文件中未出现的旧记录不会因省略而自动删除。

### 3.2 分析员提交预览

1. 在“选择本次成本文件”中选择一个或多个 CSV/XLSX。
2. 点击“校验并预览”。上传或选择文件本身不会发布数据。
3. 在“本批次预览”核对提交人、基于的数据版本、业务月份，以及“新增”“修订”“重复”数量。
4. 逐项核对差异表中的操作、字段、原值、新值、来源、工作表和记录序号。需要交接时点击“下载差异清单”。
5. 处理红色错误；展开“明细完整性提示”查看缺失明细等提示。预览无硬性错误并不表示所有分析资料都已完整，正式报告还会检查本期明细完整性。
6. 没有确认权限时，页面提示“预览已持久保存，请由财务主管在待确认批次中复核。”通知有相应范围权限的主管处理。

### 3.3 主管确认生效

1. 主管进入同页，在“主管待确认批次”中选择提交批次，并重新核对“本批次预览”。
2. 在“本次业务操作”中选择“新月份新增”或“历史修订”。修订已有记录，或补录被识别为历史期间的记录时，使用“历史修订”，填写“修订原因（历史修订必填）”。
3. 勾选“已核对业务月份、差异及校验提示”，点击“确认生效”。有校验错误、未勾选或企业模式由原提交人自批时，按钮不可用或操作被拒绝。
4. 看到“数据版本 V… 已生效。”后，确认的新版本才供报告、看板和对标共用。若提示“内容相同，无需更新。”，表示本批无有效变化，不应反复发布追求新版本号。
5. 展开“查看当前数据”，在“数据表”中核对生效内容；有审计权限者可展开“历史版本”。

企业模式必须由另一位有相应权限和范围的财务主管复核发布。local 的同人操作会显示演示说明。

如果提示“数据已被其他操作更新，请重新预览”，请用当前版本重新执行“校验并预览”并复核新差异，不能继续确认旧预览。

### 3.4 月度关账与授权重开

有期间管理权限的主管展开“月度关账与授权重开”：

1. 在“业务期间”中选择工厂、产品和月份，查看当前状态与状态版本。
2. 在“目标状态”中选择“关账”或“重开”。
3. 填写“关账 / 重开原因”，点击“保存期间状态”。两类操作都必须说明原因。
4. 对已关账期间进行历史修订前，先授权重开，再预览、复核并确认修订。后续修订报告应说明重述原因。

这里的期间状态按工厂、产品、月份管理，不另按产品规格拆分。状态若已被他人修改，刷新后复核再保存。重开和修订不会自动改写已经冻结的旧报告。

## 4. 知识登记、确认版本与发布索引

### 4.1 查看已有知识

进入“知识文档库”，展开“已登记文件与历史版本”。先看文档、版本、来源文件、可见性、适用范围、生效/失效日期、确认时间和“当前发布”。通过“查看文档”“版本”选择具体版本，阅读“已确认原文”，必要时点击“下载原件”。

“未纳入或清单不可见”不能单独用来判断知识未发布：范围受限的用户可能无法看到完整发布清单，但仍能检索自己有权访问的已发布资料。知识是否可用于某次分析，还需满足授权、业务日期及产品/规格等条件。

### 4.2 上传或登记原件

知识管理员在“上传或登记原件”操作：

1. 在“文件来源”选择“上传文件”，使用“选择 PDF / DOCX / TXT / CSV（最大 20MB）”上传资料。local 全范围知识管理员还可选择“选择项目已有原件”，再从“项目原件”列表选文件；这是受限列表，不是任意路径输入。
2. 展开“先查看原件内容”，核对“解析原文”、提取方式和 SHA256。解析有错误时先修正文档。没有可提取文字的扫描 PDF 需先完成 OCR 后再登记。
3. 在“登记方式 / 更新文档”选择“登记新文档”或“更新：…”对应文档。更新已有文档时保留原标题；同标题已存在时应选择更新。
4. 填写“文档标题”，选择“资料类别”：通用制度、产品工艺、配方资料、市场参考或其他。
5. 选择“依据用途”：默认“仅背景参考”；确经核准的资料可选择“可用于机制解释（仍不能证明本期真实发生）”。文档机制不能直接证明本期发生了某项采购、生产或经营事件。
6. 选择“可见范围”。“限定工厂与产品”需在“适用工厂（逗号分隔；公开资料留空）”“适用产品（逗号分隔；公开资料留空）”中填写明确名称，不能使用 `*` 扩大范围。“组织公开资料（明确核准）”仅向具备全部工厂和产品范围的知识管理员提供，公开资料的这两个范围字段留空。
7. 核对“适用规格（可选；需确认后才作为报告文档依据）”“业务生效日期”。如有截止日期，勾选“设置业务失效日期”，再填写“业务失效日期（仅勾选时应用）”；失效日期不能早于生效日期。
8. 点击“生成差异预览”。此时尚未确认新版本。

### 4.3 确认知识版本

1. 在“待确认差异”查看正文差异、适用范围、可见性、生效日期和元数据变更。即使正文不变，范围或日期调整也可能形成新版本。
2. 填写“登记 / 更新原因”，勾选“已核对正文、适用范围、生效日期与差异”。
3. 点击“确认登记此版本”。成功后提示“已确认版本 v…，请选择该版本发布索引。”；旧版本保留。
4. 放弃当前预览可点击“清除本次预览”。如果提示正文与业务元数据均相同，不必重复创建版本。若提示预览后产生新版本，应重新查看差异。

知识确认和成本/报告/任务的独立主管审批不是同一流程。当前知识登记页面没有“主管待确认批次”式的跨用户交接列表；具备登记和确认能力的知识管理员按本页流程处理。仅有 supervisor 的账户可发布已有确认版本的索引，不能据此推断它能登记新原件。

### 4.4 发布索引并核对检索

1. 到“索引发布与状态”，查看当前发布及发布历史。若可见，展开“当前发布清单与检索能力”。
2. 在“本次发布包含的确认版本（保留历史版本以支持历史日期查询）”中选择确认版本。需要历史日期检索时，保留相应历史版本；发布以本次选择清单为准。
3. “构建本地向量索引（需已安装并配置本地模型）”按部署能力选择。未勾选时发布 BM25 与图谱索引，并标记向量检索降级；不能把它说成完整向量检索已启用。勾选也不等于构建成功，应查看发布结果。发布失败时保留上一发布。
4. 点击“构建并发布索引”，记录页面显示的发布 ID。
5. 展开“按业务日期检索已发布知识”，填写“查询产品（可留空）”“查询工厂（可留空）”，选择“业务有效日期”，输入“检索内容”，点击“查询已发布知识”。
6. 核对发布 ID、检索模式、来源、版本、生效日期和文本。出现“无可用依据”时，依次检查授权范围、确认版本是否纳入发布、业务有效日期及查询内容；不要把无结果编成证据，也不要随意扩大公开范围。

有知识审计权限者可以展开“版本操作记录”。业务生效日期、版本确认时间与索引发布时间分别表达不同含义，不能混用。

### 4.5 local 的赛方资料核准导入

只有 local 全范围知识管理员可见“赛方资料核准导入”。如确需使用该功能，先阅读核准清单和日期说明，勾选“已核对核准清单、授权范围和演示生效日期说明”，按能力选择“同时构建本地向量索引（首次加载可能较慢）”，再点击“按已核准清单登记赛方资料并发布”。

页面说明该核准清单包含九份原件，并保留已知条号、配方换算和设备数量冲突标注。`2025-01-01` 是演示回溯基线，不代表原文件真实法律或业务生效日。此按钮会登记并发布资料，应按实际需要使用；本文没有执行或声称该动作已成功。

## 5. 模块二：产品看板与成本归因

该页主标题为“产品成本分析”，当前业务口径为中药一厂。拥有二厂数据权限不等于该页会自动切换到二厂；两厂比较应进入模块三。

1. 选择“分析产品”和“分析月份”。产品有多个规格时，再选择“产品规格”；只有一个规格时自动采用该规格。
2. 查看单位成本、本月产量、本月总成本、总成本环比变动四个指标。展开“查看分析口径”，确认金额与单位。
3. 查看截至所选月份的最近六个月趋势、当月构成和总成本变动瀑布图。缺少连续上月时，环比和瀑布分解可能不可用，不能当作零变动。
4. 在“成本要素变化率”中使用“比较口径”切换“环比变化率”或“同比变化率”。
5. 展开“查看同源明细与导出数据”，核对表格，点击“下载金额归因 JSON”保留计算结果。
6. 需要查文档时，展开“知识依据检索”，编辑“检索问题”并点击“检索知识库”。该处按当前产品、中药一厂和分析月月末业务日期检索授权的已发布有效版本；查看来源版本、发布信息及降级提示。
7. 在“成本归因分析”点击“生成归因分析”。有分析权限时，页面也可能先显示确定性数据摘要；点击按钮后的模型结果仍须根据“AI 辅助分析”或“数据分析摘要”、生成状态来判断。
8. 展开“生成耗时与诊断”，检查最终采用状态和诊断；逐段核对分析和“查看…的来源文档”。首次回复未通过业务校验时，系统可能在剩余时限内修订一次，诊断会保留首次拒绝及修订结果；最终采用后仍须人工核查。波动阈值告警只表示对应要素环比波动超过 ±10%，不证明某个经营原因成立。
9. 需要存档时点击“保存本次分析快照”，之后去“分析档案与更新记录”查看；点击“下载分析正文”取得文本。需要进一步复核时展开“查看完整数值分析”及“查看计算JSON与生成检查”。

瀑布、贡献度和归因采用金额口径：

- 要素变动额＝本月要素单位成本 × 本月产量－上月要素单位成本 × 上月产量，单位为元。
- 贡献度＝要素金额变动 ÷ 总金额变动 × 100%。总变动为零时贡献度无定义；方向相反的项目可能为负，不能把贡献度当作当月成本构成占比。

模型未配置、超时、接口失败或输出未通过数字与引用检查时，页面保留计算结论并显示状态。只有按钮带“AI”或页面成功展示文本，不能证明发生了可用的真实模型调用。市场参考、工艺机制和待核查假设也不能直接写成已查明的采购价格、生产损耗或其他经营原因。

## 6. 模块三：跨厂对标与差异拆解

进入“模块三 · 对标分析”，页内标题是“跨厂成本对标”。依次选择“对标月份”“对标产品”“产品规格”。只比较同产品、同规格、同月份的中药一厂与中药二厂记录；缺少一厂或二厂对应记录时，按页面原因先补齐，不能替换为近似产品、其他规格或其他月份。

### 6.1 ① 找差异

查看“一厂单位成本 · 元/盒”“二厂单位成本 · 元/盒”“单位成本差 · 元/盒”“相对二厂差异率”，再查看两厂产量和实际总成本。展开“比较口径与源记录”，核对公式、源文件、工作表、记录序号及可用的 SHA256 信息。

单位成本差为一厂减二厂；差异率分母为二厂单位成本，二厂为零时不可计算。实际总成本用于观察生产规模背景，不能直接把两厂实际总成本相减当作同口径节约额。

### 6.2 ② 拆结构

查看“三要素标准化金额差”及材料、人工、制造费用结构表：

- 各要素标准化金额差＝（一厂该要素单位成本－二厂该要素单位成本）× 一厂产量。
- 正值表示一厂较高，负值表示一厂较低。该数值是统一产量下的会计比较情景，不代表已经实现或必然能够实现的节约。
- 差异贡献度＝要素标准化金额差 ÷ 全部标准化金额差。净差额为零时无定义；反向项目可能为负。

核对标准化金额差合计、未舍入计算勾稽差额，以及页面可能提示的分项舍入差额。

### 6.3 ③ 核查原因

1. 先读“已确定的结构差异”；金额和结构来自源表计算。
2. 具有两厂相应产品分析权限时，可点击“生成 AI 跨厂原因分析”。查看其实际显示的“AI 辅助解释”或“规则分析”、生成状态及回退原因。
3. 阅读“一厂原料核查明细”、各段“待核查解释”“缺少证据”和引用来源。页面提供一厂原料明细时，二厂对应明细仍可能标为“未提供”，不能据此编造两厂采购单价、用量或效率差异。
4. 在“核查建议”查看动作和责任岗位，可点击“下载核查建议 JSON”。
5. 要交接整改时，选择“转为整改任务的建议”，点击“AI 生成持久草稿任务”，核对保存提示中的实际生成方式，再点击“打开整改任务”补全责任人并提交审核。跨厂来源在任务类型中映射为“专题分析”，任务仍保留两厂范围，后续操作人须具备相应两厂权限。
6. 需要技术复核时，展开“查看对标计算与生成检查”。

### 6.4 多产品汇总

打开“多产品汇总”，查看所选月份各产品和规格的对齐结果，可点击“下载本月对标汇总”。不同产品的单位成本或差异率不直接合并、平均；汇总不能替代逐项同口径检查。

## 7. 模块一：冻结报告、审核与导出

### 7.1 选择参数并生成草稿

1. 进入“模块一 · 智能报告”，页内标题为“成本智能报告”。有一厂报告生成及数据权限时，出现“分析参数”。
2. 选择“目标产品”“产品规格”“分析月份 / 季度内月份”，再选“报告主题”：月度成本分析、季度成本分析、专题分析。专题分析还需在“专题重点”中选择材料、人工或制费。
3. 季度采用自然季度，不是滚动三个月。例如选择 2026-05 的季度报告对应 2026 年第二季度，需要该产品和规格的 4、5、6 月本期汇总。季度产量和金额按全季求和，单位成本按产量加权，不能用一个月代替全季。
4. 核对“按正式报告完整性要求生成（缺期资料会阻止生成）”。本期成本汇总需要完整覆盖期间；正式要求本期材料、人工、制造费用明细齐备并勾稽。取消勾选仅用于资料完整性核查稿，不解除本期汇总等基本校验，也不能把核查稿批准为正式报告。前期、上年同期或预算不完整时，以页面警告为准，相应比较指标可能不计算。
5. 根据业务需要勾选“包含同产品同规格同期跨厂对标”。跨厂内容还需要二厂相应产品的读取和报告生成权限。
6. 选择是否“使用已配置模型辅助解释”。未配置或未产出可用模型结果时，会保留规则分析并说明状态。
7. 点击“生成并保存报告草稿”。成功提示是报告已保存为待复核草稿；生成时的数据、证据、来源和版本随报告冻结。后续确认新成本、发布新知识不会自动替换旧报告内容。

### 7.2 核对并提交审核

在“报告档案与审核”中用“选择报告”打开记录，核对：

- “审核状态”“状态版本”“生成方式”，以及产品、规格、期间和主题。
- 分析正文、各节“缺少证据”、警告和“改进建议”。
- “期间口径、来源与版本”中的期间、校验、数据版本、知识索引发布及源记录。

确认可以送审后，点击“提交主管审核”。状态从“草稿”或“已退回”转为“待主管审核”。报告正文没有在本页直接修改的表单；若事实、资料或参数需要变更，应补齐并确认数据/知识后生成新报告，保留原冻结报告供追溯。

### 7.3 主管审核签发

1. 另一位有相应产品及全部涉及工厂权限的主管选择待审核报告。
2. 填写“审核意见”，点击“批准并签发报告”或“退回报告”。批准和退回都要求审核意见。
3. 企业模式禁止报告创建人自批；local 会显示模拟独立主管审批说明。资料完整性核查稿不能批准签发。
4. 批准后状态显示“已审核签发”；退回后显示“已退回”，原冻结内容保留。
5. 展开“报告审核记录”核对记录。若提示审批状态已变化，请刷新并确认当前状态版本后操作。

报告冻结的是输入和生成内容；“状态版本”记录审核决策变化。保存为冻结草稿不等于已审核签发。

### 7.4 准备并下载 Word / PDF

1. 到“报告导出”。尚未批准时点击“准备草稿 Word”或“准备草稿 PDF”；批准后对应按钮为“准备正式 Word”或“准备正式 PDF”。
2. 准备成功后，点击对应的“下载草稿 Word”“下载草稿 PDF”“下载正式 Word”或“下载正式 PDF”。准备按钮本身不是浏览器文件下载。
3. 草稿文件标注“草稿／未签发”，正式文件绑定当前审核版本及同一冻结内容。Word 与 PDF 来自该报告的冻结内容，导出不会重新读取最新数据、检索知识或生成分析。
4. 下载前仍会核对当前权限。来源授权撤销、内容校验失败或导出异常时，按错误处理，不要用旧页面缓存绕过。

如需转为整改任务，在“从报告建议生成整改任务”选择“选择改进建议”，点击“AI 生成持久草稿任务”，核对实际生成标签，再点击“打开整改任务”。报告审核状态与任务审核状态分别跟踪；生成任务草稿本身不代表任务获批或已发送。

## 8. 模块四：任务编辑、审核、签发与 mock 回执

该页标题是“整改任务与跟踪”。页面明确说明：发送仅连接官方本机 mock（`127.0.0.1:8090`），消息及生命周期均为模拟，不代表真实微信送达或实际整改完成。真实生产 RPA 发送和查询未启用。

### 8.1 新建或接续草稿

1. 在“任务对象”选择“新建草稿”，或选择从报告/跨厂建议保存的任务。选项包含唯一任务ID、内容版本和工作流状态；同名任务应按ID核对，不能只凭标题选择。
2. 新建时选择“任务产品”“任务涉及工厂”。已有任务的工厂和产品范围不能通过编辑改变。
3. 在“人工编辑与责任分配”中填写“任务标题”“责任人姓名（提交必填）”“责任部门（提交必填）”“责任岗位（可选）”。责任人和责任岗位不决定当前登录账户的权限。
4. 选择“优先级”（高/中/低）、“计划截止日期”“分析类型”（月度成本分析/季度成本分析/专题分析），填写“分析月份（YYYY-MM）”“分析结论与来源”“核查内容与交付要求”。至少保留有效的分析月份、产品、来源结论和工厂范围，不能把完全空白表单当作可保存任务。
5. 点击“保存持久草稿”。新建时也可点击“AI 生成并保存任务建议”，但必须查看最终生成标签：“AI建议，待人工复核”“规则建议（AI不可用或输出校验失败），待人工复核”或“人工草稿”。模型不会替用户任意指定责任人姓名，缺失姓名需人工补全。
6. 核对保存后的任务 ID、内容及版本。对未签发任务再次编辑保存，会形成新内容版本并使既有批准失效，需要重新提交和审核。

### 8.2 提交、批准与签发

1. 补齐标题、责任人姓名、责任部门、截止日期及来源等必填字段后，点击“提交任务审核”，状态变为“待审核”。
2. 主管打开任务，核对来源、核查动作、责任分配、范围、截止日和当前版本，填写“主管审核意见”，点击“批准任务”或“退回任务”；退回时必须写明原因。
3. 企业模式禁止创建人以及当前内容版本的编辑人批准自己的版本，需要另一位主管复核。local 页面的同人批准是模拟审批。
4. 批准后为“已批准”，仍未发送。由有发送权限者点击“签发批准版本”，该批准版本进入队列，工作流变为“已签发”，发送状态通常显示“等待发送”。
5. 已签发任务不能继续编辑，即使发送失败或结果待确认也不能修改内容、换 ID 或重新创建相同任务来绕过核对。

### 8.3 发送与查询

1. 在已签发任务中，点击“发送到官方 mock / 执行到期重试”。此按钮处理当前任务已到期的发送/核对工作；未到重试时间时不保证发生新的尝试。
2. 点击“查询官方 mock 回执”取得当前远端观察结果。此操作只查询，不发送新任务。
3. 分别查看“工作流”“发送状态”“回执状态”，并核对下方最近错误、发送尝试次数、查询核对次数和下次尝试时间。
4. 已显示“mock 已受理”时，发送按钮禁用；继续查询回执以了解模拟生命周期。页面没有承诺后台 worker 已运行，也不能仅因存在下次尝试时间，就断言后台会自动完成重试。
5. 展开“当前任务 JSON 与回执”，必要时点击“下载当前任务记录”。“任务版本”展示内容版本；有任务审计权限者可查看“审批、发送与回执审计”。

### 8.4 分开理解三类状态

| 类别 | 状态代码与页面标签 | 操作含义 |
| --- | --- | --- |
| 工作流 | `draft` 草稿；`submitted` 待审核；`approved` 已批准；`rejected` 已退回；`issued` 已签发 | 表示内部审核和签发进度。已批准仍需签发；已签发不代表 mock 已受理。 |
| 发送 | `not_sent` 未发送；`pending` 等待发送；`sending` 发送中；`retry` 等待重试 | 核对当前记录和下次尝试时间；重复点击不会重置批准、发送次数或重试上限。 |
| 发送 | `unknown` 结果待确认 | 可能已受理但尚未得到可靠结果，必须按原任务 ID 查询核对。 |
| 发送 | `failed` 发送失败 | 查看错误与审计；达到上限或存在永久错误时不能靠重复点击恢复发送。 |
| 发送 | `accepted` mock 已受理 | 仅证明 mock 的模拟受理，不是微信真实送达。 |
| 回执 | `sent` 模拟已发送；`received` 模拟已接收；`confirmed` 模拟已确认；`in_progress` 模拟进行中；`completed` 模拟已完成；`overdue` 模拟逾期 | 均为官方 mock 生命周期；“模拟已完成”不能当作真实整改结案。无回执时显示“尚无回执”。 |

### 8.5 unknown、超时和重复 ID 的处理

- 遇到 `unknown`、传输中断、响应格式无效、回执 ID 不符或重复 `task_id` 提示，先保留原任务 ID、批准版本和错误，使用“查询官方 mock 回执”核对。重复 ID 本身不等于发送成功，还须匹配远端内容与批准版本。
- 对曾经发送结果不明的任务，即使查询返回未找到，也不能排除先前已受理后 mock 重启的情况。系统对此仅继续核对，禁止自动重发；不要自行换 ID、重新创建相同业务任务或删除记录尝试重发。
- 已受理任务如果在 mock 中消失，保留本地已知回执，并联系维护人员确认是否重启；不能据此重新发送。
- `retry` 表示可按系统规则执行有限重试，`unknown` 表示结果需核对，两者不能混为一谈。“无自动重试”或达到上限后，应人工核查；查询操作也不会重置终止失败为新的发送机会。
- 同 ID 的远端内容与批准版本不一致时，停止发送并交管理员核对审计。不要覆盖远端任务，也不要仅凭标题相似判断是同一批准版本。

## 9. 分析档案、更新记录与历史回看

进入“分析档案与更新记录”，页内标题为“分析档案与更新追溯”。

1. 在“分析快照”中选择“业务月份”“分析记录”，查看此前在模块二保存的正文。
2. 展开“快照证据与数据版本”核对版本、来源和代码摘要；点击“下载完整分析快照”可下载保存结果。
3. 打开历史快照不重新检索、不调用模型；下载前仍会核对当前权限。当前无一厂档案权限或未保存快照时会提示无可用档案。
4. 在“更新记录”中，有财务主管或审计权限者可看成本修订记录；这里只展示当前用户有权查看的完整修订批次。
5. 知识原件、版本和发布时间回“知识文档库”查看；报告及其审核记录回“模块一 · 智能报告”查看；任务版本和回执审计回“模块四 · 整改任务”查看。它们不全部归入“分析快照”。

历史数据修订或知识更新后，旧快照、旧冻结报告仍表示保存时的结果。需要反映最新已确认资料时，重新生成并保存新的分析或报告。

## 10. 系统设置与运行检查

本页由系统管理员进入。先查看“身份模式”“模型凭据”“任务发送通道”；“已配置”只是检测到配置，不等于已连通或业务模型输出通过检查。

1. 在“模型 API 配置”填写“OpenAI 兼容接口地址”“模型名称”“API 密钥”。密钥不会回显，保存时模型名称与密钥必填。
2. 外部接口需使用 HTTPS，并确认“已确认外部接口及分析数据的使用权限”。此勾选不赋予业务数据权限；业务调用仍以既有授权为前提。
3. 点击“保存模型配置”。成功后密钥输入清空，连通状态回到待验证。
4. 点击“验证模型连通”。该操作会向配置的模型接口发送不含业务数据的 JSON 连通请求，并非纯本地检查。
5. 若显示“当前会话已通过模型 JSON 连通验证。具体业务输出仍需各模块校验。”，只表示本次会话的这项连通检查成功。继续到相应业务模块查看真实生成状态、输出校验及证据，不得据此写成全部 AI 功能已验收。

模型调用未配置或失败时，相关业务页可显示规则分析或确定性摘要。保存配置不代表调用成功；连通检查与各业务模块的生成结果分别保存、核对，不以操作说明替代实际运行记录。若服务端环境配置覆盖了页面保存值，由部署人员核对实际生效配置。

“已接入能力与部署验收”表列出能力及待在部署环境核验的事项，不是“已全通过”清单。其中涉及企业 OIDC 授权与撤权、实际知识检索质量、模型文字人工复核、mock 端到端回执、备份恢复、并发容量和运维监控；真实微信未启用。系统设置没有自由填写登录角色、组织或授权范围的入口。

## 11. 常见提示与处理原则

| 现象或提示 | 推荐操作 |
| --- | --- |
| 菜单不存在、“当前角色无权执行此操作”、无权访问工厂/产品 | 先核对登录账户和授权范围，联系授权管理员。页面输入和业务字段不能改变权限。 |
| “表头不能唯一识别”、月份格式错误、重复主键、金额不闭合 | 回到下载模板及源文件修正，再整批校验预览；不能把校验错误当作可忽略告警。 |
| 缺少明细提示 | 核对需要的本期明细并补齐。允许预览/确认与正式报告完整性是不同检查。 |
| 成本预览、知识预览、期间状态、报告状态或任务版本已变化 | 刷新并重新读取；涉及输入版本时重新预览，再按当前版本复核。 |
| 历史期间已关账 | 由授权主管填写原因重开，再走历史修订；后续报告说明重述原因。 |
| 知识解析失败或扫描 PDF 无文本 | 修正文件或先完成 OCR，重新核对解析原文后登记。 |
| 无可用知识依据、完整发布清单不可见、向量降级 | 分别核对范围、日期、确认版本与发布清单，以及部署的本地模型能力；不能据此编造证据或声称完整向量检索通过。 |
| 看板无连续上月、二厂数据缺失、分母为零 | 接受“—”“不可计算”“无定义”或缺失提示，补齐同口径记录；不要按零补齐或混用产品规格。 |
| 模型未配置、超时、输出校验失败 | 查看生成状态及回退原因，保留可复核的计算结论；由管理员核对配置。规则结果不能标作真实 AI 调用成功。 |
| “报告未生成”、正式报告完整期校验失败 | 检查完整期间、规格、明细与汇总；如生成核查稿，明确其不能签发。不要用某月结果冒充季度。 |
| “导出未完成”或来源授权失效 | 保留报告 ID、状态版本与错误，交维护人员核对权限、内容完整性和导出依赖；不要修改已冻结结果规避。 |
| mock 无法连接 | 保留任务记录，联系维护人员检查官方 mock；按有限重试规则处理，不能写成已送达。 |
| mock `unknown`、重复 ID、回执冲突或已受理后查不到 | 按第 8.5 节用原任务 ID 查询核对；不要盲目重发、换 ID 或重复创建。 |

交接问题时记录页面名称、业务对象及期间、批次/报告/任务 ID、当前版本、可见状态和错误原文，避免只描述“失败了”。涉及模型密钥的输入不要附在问题记录中。
