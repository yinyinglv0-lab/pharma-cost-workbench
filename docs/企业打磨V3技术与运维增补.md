# 企业打磨 V3 技术与运维增补

本文件是对原 README 和部署手册的新版补充。旧交付文档、报告、视频、评分表和 V2 源码包保持原样。完整审查见 `delivery/polish-v3/企业交付审查与打磨报告.md`；运行与测试证据见本轮交付清单。

## 交付定位

当前提供的是有授权、来源追溯、持久审核与故障记录的单组织试点基线，不是已经通过真实药企生产验收的通用 ERP 产品。赛题实际数据含中药一厂/二厂及三种产品；模块一、二明确按一厂分析，跨厂对标比较两厂，不能仅改名称就宣称支持任意企业组织。

正式归因合理性评分由赛方评委完成。内部专家预审可选，不要求用户自行找到专家并填写正式得分；未评项保持空白，不填零，不以自动检查代替。程序复算、引用约束通过也不等于业务原因已确认。

## 本轮关键变更

1. Agent 预测复用单次已授权快照，应用内部适配器再次鉴权并校验修订号/数据哈希。客户端不可提交快照、工具计划或任意代码。
2. M2 与 Agent 共用知识适用性策略。文档可读不等于每个产品章节可用于归因；错误产品/规格片段排除，旧版缺适用性元数据仅作背景。M1 原有证据边界保持。
3. API 的单厂看板/归因显式筛选一厂，避免合法二厂预算混入；报告仍保留跨厂对标。
4. 助手意外运行错误返回 `status=failed`、`error.code=service_unavailable`、关联错误编号；HTTP 503。日志仅记错误类型、操作与编号，不记录输入、异常正文或凭证。
5. 任务仓库增加 `page(actor, status=None, query=None, limit=100, offset=0)`，返回 `items/total/limit/offset`。租户、产品、所有涉及工厂先在 SQL 中过滤，再分页；结果仍逐条复核权限。查询为字面包含，`%`/`_` 不作通配。旧 `list` API 保持兼容。
6. UI 使用统一原生主题，报告生成/审核分视图，任务搜索翻页，金额按千分位和两位小数显示，看板四项 KPI 稳定成行、图表分视图。

## 启动与访问

在当前 Windows 工作区使用项目解释器，不使用依赖不全的全局 Python：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m pip check
.\.venv\Scripts\python.exe -B -X utf8 launch_system.py --no-browser
```

本次驻留供验收的服务使用 `--no-browser --no-worker`，只启动界面与API，不自动派发或轮询任务。需要自动任务处理时，由授权操作者确认业务状态后另行启用worker；未运行worker不影响只读分析。

本机入口为 `http://127.0.0.1:8501`，API 为 `http://127.0.0.1:8000`。端口已被其他服务占用时，启动器保留对方并选空闲端口，应以控制台打印 URL 为准。不得停止未知进程以抢占端口。官方 mock 的 `8090` 是独立服务，不等于真实微信通道。

新机器准备 Python 3.12 虚拟环境，并按 `requirements.txt` 安装核心依赖；本地 BGE 模型需 `requirements-models.txt`、合规取得的权重及足够资源。纯源码包不含原始 CSV、正式模板、知识原件、已建索引、受控数据库、模型权重、字体或任何凭证，不能被当作完整业务数据包。

## 配置与部署身份

- `.streamlit/config.toml` 与 `deploy/streamlit.config.toml` 的 `theme` 完全一致。前者仅含主题、最小工具栏及关闭遥测；后者继续保留 CORS、XSRF、上传限额、隐藏错误详情等部署约束。
- `/api/health.source_fingerprint` 继续表示应用 Python 源码身份。
- `/api/health.deployment_fingerprint` 为 `deployment-files/1.0`：在应用源码外，还对明确列出的非敏感依赖声明、部署配置、运行脚本、ECharts 和本项目字标取哈希，缺失文件也参与身份。启动器复用服务前同时核对两者。
- 这两个哈希都不是容器镜像 digest，也不证明已安装 wheel、字体、权重和环境变量与声明一致。部署仍应另存镜像 digest、安装清单、数据/知识版本和启动日志。
- 指纹不读取 `.env`、`secrets.toml`、真实授权映射、模型密钥或业务数据库。

## 原运维手册勘误

原 `docs/部署与运维手册.md` 的 WQY 默认字体描述已不符合当前 Dockerfile。当前镜像默认配置的是固定来源和哈希的 `NotoSansSC-VF.ttf`；本机可通过 `REPORT_CJK_FONT` 指定有权使用且支持完整中文的 TrueType 字体。源代码包不分发字体。

原 README/手册中的源码文件数量、九个 CI 测试文件等属于历史交付，新的数量以 `SOURCE_MANIFEST.json` 为准。此次 CI 配置增加规则助手、预测基线、任务授权分页和部署身份测试；本地验证不等同于已运行远端 CI。本轮没有推送仓库或触发远端工作流。

## 数据与分析口径

- 要素金额 = 当月产量 × 要素单位成本；金额变动 = 本期金额 - 连续前期金额。
- 贡献度 = 要素金额变动 / 总金额变动。总变动为零时无定义，不能分摊成 0% 或强行凑 100%。显示舍入造成 0.01 个百分点差异单独解释，不改原数。
- 顺序替代分解为产量影响 `c0*(Q1-Q0)` 与单位影响 `Q1*(c1-c0)`。这是会计桥接，不证明采购、返工或能耗原因。
- 两厂金额差用一厂产量标准化；不是实际已经节约的金额。不同规格/产品不合并单位成本平均值。
- 预测只有下一月单位成本的 naive/ma3 基线。两段六个月历史之间缺 2025-07 至 12，不跨缺口训练；六月截点只有三个共同历史检验月。没有校准区间、未来产量或总成本预测，也不自动选误差最小方法。
- 词项二部图用于检索，不是领域因果知识图谱；嵌入模型不是小模型业务抽取；规则助手不是 LLM 自主规划 Agent。

## 审核与安全边界

报告生成只保存草稿；提交、主管复核、签发、导出和任务生成分别操作。企业身份模式执行职责分离；本机 OS 演示不应暴露公网，模拟审批不代表企业签署。

只读助手不能审批、签发或发送。报告参数预填在目标页重新校验，不自动保存。每页重新检查身份，主体/角色/工厂/产品范围变化后清空会话结果，避免旧视图泄漏。

任务分页提升返回规模控制，不构成容量认证。SQLite 的 JSON 范围检索仍可能扫描租户记录；十万级以上任务需在真实目标环境压测后考虑规范化授权索引表、专用数据库和归档策略。报告历史库也保留既有实现，未宣称所有仓库完成数据库级分页。

## 验证与再生成

所有 pytest 通过根 `conftest.py` 使用临时数据库和空模型配置，真实业务库不用于测试审批或发送：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe -B -X utf8 artifacts/polish_v3/data_deploy_audit/verify_decimal.py
.\.venv\Scripts\python.exe -B -X utf8 artifacts/polish_v3/core_audit/verify_core_after.py
```

`scripts/audit_polish_ui.py --stage after` 对现有 UI 做只读页面与页签检查；`scripts/verify_polish_live.py` 检查 API、预测、助手预填和只读前后业务记录。浏览器需要已安装 Edge/Playwright；受限环境的管道访问可能需单次明确授权。

生成封面与PPT：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts/build_polish_covers.py --screenshots artifacts/polish_v3/ui/after --check-html
```

它仅重建本轮 `covers/` 内自身输出，不覆盖旧模板和冻结报告。Word/PPTX为可编辑文件；PDF/PNG由共享文案/布局独立生成，不伪称 Microsoft Office 实际渲染。阅读环境的字体替换与分页需接收方实际打开确认。
