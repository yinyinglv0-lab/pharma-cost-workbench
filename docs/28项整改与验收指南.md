# 28项整改与验收指南

本次整改以28项审查记录为基线。原审查交付、历史知识发布、冻结报告和已签发版本保留；新结果使用新的代码、知识发布和报告渲染版本。具体测试次数、实际模型采用情况和评分以本轮交付中的验收结果为准。

## 成本归因与自然语言

金额、产量、单位成本、贡献度及桥接由程序计算。模型只补充有引用的解释和核查行动，不能改写计算结果。假设和建议共用会计方向约束：固定费用总额不变时，产量减少不能造成单位分摊降低。“可能”“待核查”及合法引用都不能使错误方向变为合格结论。

正文直接说明计算发现、引用原文和实际缺口，不加“已确认事实／推测机制／证据边界”等分层标签。市场报价仍是市场参考，不是本厂采购实价；通过市场价反算的情景单耗保留在机器结果中，不作为实际消耗写入阅读正文。

已经提供的人工总工时可用于“工时×归集费用/工时”的金额桥接以及“工时/盒×归集费用/工时”的单位成本桥接。每工时产出是计算指标，不能自动等同于人员绩效或工艺改善。工资结构、员工考勤和加班审批仍需原始记录核查。

## 对标与明细

两厂必须同产品、规格和月份。单位差为一厂减二厂；标准化金额统一乘一厂产量，不能作为已实现节约。差异率以二厂单位成本为分母，零分母保留空值。绝对值小于1%的比例采用四位有效数，大比例通常保留两位小数，统一ROUND_HALF_UP，并同时保留精确十进制字符串。

材料、人工及制造费用均可下钻。现有受控导入支持同一类型表内的两厂记录，主键包含工厂、产品、规格、月份及明细名称；二厂资料缺失时，配对差额保持空值，不以一厂明细推造二厂。结构树列出已配对金额与尚未落实到配对细目的剩余金额。补资料后仍须通过明细与汇总勾稽。

## 图表与知识引用

看板通过Streamlit v2组件接收真实图表点击。趋势点、结构扇区、变动柱和热力单元格的月份与要素由服务器使用现有图表数据重新确定，不信任浏览器传回的名称。产品、规格、月份、权限范围、数据或分析代码变化后，旧问题和旧证据失效。普通重绘保留用户编辑的问题；点击新图点则生成该点的问题并自动检索。

归因与对标正文中的引用ID在服务器端替换为企业蓝色角标。悬停显示摘要，点击固定显示全文、完整文件名、文件类型、来源定位和真实检索分数；再次点击、关闭按钮、Esc或点击外部可收起。触屏支持点击，卡片在视口内避让。缺少检索分数的核算记录明确显示未提供。文件名、原文和模型文本全部转义，不执行来源中的HTML或脚本。组件只使用现有证据，不自行检索或补造引用。

## 知识发布与就绪

新知识发布包含版本化实体、提及和关系索引，区分直接原文支持的关系与同片段共现。配方、工艺、设备、指标的关系必须有对应引文、字符偏移和业务适用范围。共现不代表工艺联系，也不代表因果；设备标准或GMP规范不证明当期实际发生事件。

原有向量、BM25与词项图支路保留，新增领域图支路以及可解释的规则重排。重排输出实际分项和前后顺序，不宣称使用神经重排器。模型预热、索引发布和业务检索是不同状态。Web与API在已认证身份下非阻塞预热，`GET /api/search/readiness`显示当前状态；`POST /api/search`可设置`require_ready=true`，未就绪时返回503与Retry-After。默认保留明确标记的降级检索。旧发布可读，不被就地改写。

集团对标知识基线只能由已有两厂成本CSV逐行推导，并保存源哈希、键和公式。模拟历史案例不能改称真实整改闭环，缺失类别仍作为资料缺口登记。

## 报告阅读版与审计附件

新报告采用`shared-docx-reportlab/3.0`。六章结构保留，加入人工桥接与对标要素贡献/抵消结构，经营观察使用实际计算结果。零差异分支不套用差异原因，不创建无必要任务。

阅读版按实际采用的来源给出短引用及精确片段，完整源对象、哈希和技术检查移到独立JSON审计附件。报告中心和`/api/reports/{id}/export/audit_json`均沿当前权限、冻结数据和审核版本导出。旧renderer及签发覆盖层继续使用原合同，不能用新排版改写历史报告。

## 从任务执行到业务验收

模型生成任务时填写受控结构化计划：核查对象、动作、凭证类别、交付物和验收判据。对象只能来自源分析；责任人、部门、岗位和期限保留可信输入。缺少人员信息时留空，审批前必须确认。默认建议期限有单独依据，不冒称已经获得业务承诺。证据记录摘要由真实逐条记录计算，不伪称为原文件字节哈希；模型不能增删源证据ID或改写冻结来源。

任务状态分为两条线：远端RPA执行回执与本地整改业务状态。远端`completed`只表示模拟执行完成，业务仍可`open`且逾期。整改人提交过程、归档凭证定位与哈希、同口径前后指标及效果评估后进入`pending_acceptance`。独立验收人可以退回为`rework`，或在执行完成且材料完整后验收为`closed`。成本增加或没有节约也可以如实验收，不能预设必须得到正收益。

提交与验收同时校验内容版本和闭环版本。分析员可提交整改，主管可独立验收与催办；作者、编辑人、材料提交人及同名责任人不能自行验收，本机演示也遵守此规则。旧库增量迁移不推定历史已关闭。

逾期按北京时间截止日判定。持久提醒至少间隔24小时，第三次起标记主管关注；没有明确主管接收人时不虚构身份。官方模拟服务确有`POST /api/notify/wechat`，新客户端使用该接口单独催办，不通过重发任务催办。连接明确失败可限次重试；超时、5xx或中断可能已送达时记为`unknown`并停止自动重发。通知中心的本人已读与外部送达独立记录。

整改凭证的归档定位、哈希和效果指标是提交人的声明，系统不会自行访问外部文件。独立验收人须核对原件。模拟通知不等于实际微信平台送达。

## 验收入口

常规定向与全量测试使用项目虚拟环境：`.venv/Scripts/python.exe -B -X utf8 -m pytest -q -p no:cacheprovider`。新增回归覆盖因果方向、引用注入、图点范围、数值精度、两厂配对、任务语义、催办不确定性和独立验收。

真实模型、正式BGE索引、浏览器及官方RPA套接字验收与单元测试分别记录。套接字用隔离库和专用本机端口，测试值明确标记为合成数据；不创建真实整改收益，不发送真人通知。报告实际排版与Word结构验证的范围分别报告，不把OOXML校验等同于桌面Word实排。
