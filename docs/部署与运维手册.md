# project4 单组织单实例部署与运维手册

本交付使用一个应用容器，包含一个 FastAPI 进程、一个 Streamlit 进程及一个受管理的任务 worker，使用本机文件系统上的 SQLite、原件和发布产物。企业身份连接既有 OIDC IdP；`COST_TENANT_ID` 固定为 `default`。不提供多租户隔离、多实例共享写库、高可用或已验证的容量/SLA。

本文命令由部署负责人在授权环境执行。运维自动化测试使用临时 SQLite/原件，Compose 执行静态校验；集成阶段的真实备份/恢复记录另行归档。核心镜像已有公开 CI 构建执行记录：[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 以 `INSTALL_LOCAL_MODELS=false` 构建不含本地模型依赖栈的核心镜像，并在断网容器中进行合成运行检查。每次提交的实际结果以对应 GitHub Actions 链接和交付索引为准，构建记录不代表所有运行检查通过，也不证明生产 OIDC 登录、可选本地模型栈或现场部署已经验收。真实数据、模型、字体、依赖和赛题附件的使用/分发授权须随交付单确认。

## 1. 交付文件与路径

| 文件/目录 | 用途 |
|---|---|
| `Dockerfile`、`compose.yaml`、`.dockerignore` | 代码镜像、单实例容器和构建上下文白名单 |
| `.env.example` | Compose 非秘密环境配置结构；必填值为空，缺少时拒绝启动 |
| `deploy/streamlit.config.toml` | 只读 Streamlit 服务配置，开启 XSRF/CORS 保护、禁遥测 |
| `deploy/streamlit.secrets.example.toml` | `[auth]` 结构，必须另存至私有路径再填写 |
| `deploy/authorization.example.json` | 空的 `users` 映射，不存在默认账户 |
| `deploy/nginx.conf.example` | 既有宿主 HTTPS 代理的示例；不安装/启用代理 |
| `deploy/compose.models.yaml` | 可选本地模型只读卷，不下载模型 |
| `deploy/compose.restore.example.yaml` | 将经核对的新恢复根目录挂载至实例 |
| `scripts/preflight.py` | 只读依赖、身份、worker授权、路径、资源、数据与哈希预检 |
| `requirements.txt`、`requirements-models.txt` | 核心运行依赖与本机BGE运行依赖；模型权重另外交付 |
| `scripts/run_task_worker.py` | 有界批次派发/回执同步进程，由容器入口一同停止 |
| `scripts/backup_restore.py`、`enterprise/operations.py` | 停写备份、归档校验、新根恢复、维护与外发阻断 |
| `deploy/generate_inventory.py` | 当前环境的组件来源/版本/哈希清单；不作许可证裁决 |

运行路径由 `paths.py` 定义：`COST_DATA_DIR` 放业务源表、上传、索引兼容数据、模板和报告产物；`COST_MANAGED_DIR` 放受控版本库、原件、索引发布、任务与期间库。容器内分别为 `/var/lib/project4/data` 和 `/var/lib/project4/managed`，共用 `cost_data` 持久卷。代码目录 `/app` 只读。

模型凭据配置单独位于 `COST_LLM_CONFIG_FILE=/var/lib/project4-private/llm.json`，属于 `cost_private` 私有卷，不进入业务备份。宿主的 OIDC 授权文件和 Streamlit secrets 以只读文件挂载。`.local/`、`.env`、密钥与授权配置不进入代码镜像；秘密的恢复由企业秘密管理系统或独立加密托管流程负责。

不将业务文件放到任意代码子目录。兼容项目根目录作为 `COST_DATA_DIR` 时，备份只选择下面第 5 节列出的业务范围；生产应使用独立数据根目录。外部符号链接、Windows junction、网络共享卷不属于备份协议。

## 2. 部署前准备与 OIDC

由身份管理员注册一个 Streamlit OIDC confidential web client，设置精确 HTTPS 回调 `https://成本域名/oauth2callback`，配置 `openid` 和所需 profile claims。令牌/用户信息需包含稳定 `sub`、可信 `iss` 和 `exp`；显示姓名不能作为权限主键。API 验证含 `exp/iat/sub/iss/aud` 的 Bearer JWT，算法为 RS256/ES256，并使用 HTTPS JWKS。API audience 是企业 API 资源标识，可能与 Streamlit 的 `client_id` 不同。

填写私有 `secrets.toml`：

```toml
[auth]
redirect_uri = "https://cost.example.invalid/oauth2callback"
cookie_secret = "由部署负责人生成的至少32字符随机值"
client_id = "IdP登记的Web客户端ID"
client_secret = "IdP分配的真实客户端秘密"
server_metadata_url = "https://identity.example.invalid/实际发行者/.well-known/openid-configuration"
```

以上域名和中文值仅解释字段，不能直接用于部署。可在可信本机生成随机 cookie secret：

```console
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

将输出直接写入私有配置，不贴进聊天、日志或提交记录。客户端秘密从 IdP 获取；没有共享默认密码。源代码中的示例 TOML 保留空值，预检会拒绝空值与常见 `replace/changeme` 占位。

服务端授权 JSON 按 IdP 实际 `sub` 映射，样例结构如下；实际文件须填入经过核准的主体与范围：

```json
{
  "users": {
    "在此替换为IdP返回的稳定subject": {
      "enabled": true,
      "display_name": "业务复核人",
      "tenant_id": "default",
      "roles": ["supervisor"],
      "factories": ["中药一厂"],
      "products": ["被授权的产品名称"]
    },
    "在此替换为worker专用稳定subject": {
      "enabled": true,
      "display_name": "任务派发服务",
      "tenant_id": "default",
      "roles": ["supervisor"],
      "factories": ["中药一厂"],
      "products": ["该服务被授权派发的产品名称"]
    }
  }
}
```

`roles` 允许 `analyst/supervisor/knowledge_admin/auditor/system_admin`，工厂/产品按业务名称精确匹配，`*` 仅在明确全域授权时使用。`system_admin` 负责系统配置/备份，不自动获得业务数据角色。删除主体、将 `enabled` 设为 `false` 或缩减范围会在后续受控操作重新读取映射；离职回收还应终止 IdP 会话并检查尚存浏览器会话。

为任务服务设置非秘密变量 `COST_WORKER_SUBJECT`，其值必须精确匹配上面独立的worker主体，不能填 `issuer|subject` 组合或任意未登记名称。该值不是token或默认账户，可信来源是受控服务器配置。当前角色模型中 `task.send` 由 `supervisor` 提供，服务身份应限制到实际允许派发的工厂/产品；`system_admin`不隐含派发权限。生产预检调用相同的 `security.worker_principal()`，缺值、停用、无task.send或空scope时在启动API/UI/worker前失败，避免启动一个持续输出认证错误的worker。worker每轮重新读取当前授权，后续撤权也必须处理告警。

设置 `.env`（先复制 `.env.example`），包括 issuer、audience、JWKS URL、`COST_WORKER_SUBJECT`、两个**已存在的绝对宿主文件路径**。宿主权限需要让容器 UID/GID 10001 读取该配置，又禁止无关用户读取；可用专用组和 `0640`，Windows 使用对应 ACL。不要为了挂载便利改为全员可读写。更新 bind-mounted 文件后重建容器以确保读取新 inode，不能假设原子替换后的旧挂载自动刷新。

IdP 信任链、代理信任根、DNS、时钟同步、HTTPS 证书续期由基础设施负责人维护。预检默认不访问网络；验收时单独执行 `--network`，验证 discovery issuer、JWKS 地址和可达性。该检查不代替一次真实登录、退出、无权限拒绝与账户撤销测试。Streamlit 身份 cookie 不能当成 API Bearer token；共享应用服务直接使用已认证 Principal。

本机演示可使用 `COST_AUTH_MODE=local`，但必须绑定 `127.0.0.1/::1/localhost`，限定一个 OS 用户，不能用反向代理扩大访问。生产 Compose 固定 `oidc`，容器入口拒绝 local。

## 3. 镜像、安装与启动

目标环境使用 Python 3.12 与 Docker Compose v2+。Dockerfile 安装 Debian CA、OpenMP 运行库、Noto CJK 与文泉驿正黑字体，PDF 使用 ReportLab；其默认可嵌入的 TrueType 字体为 `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`，不能假设 Noto CJK 的 CFF TTC 可由 ReportLab TTFont 读取。不需要宿主 LibreOffice/Word。镜像构建会下载批准的基础镜像、OS 包和 Python 依赖；**运行阶段**设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，不自动下载模型。严格离线现场应由 CI 预构建镜像并导入，或事先制作批准的 wheel/OS 镜像缓存，不在现场临时联网补依赖。

`requirements.txt` 为不含torch的核心依赖，包含pypdf、ReportLab、PyJWT/crypto和Authlib；`requirements-models.txt` 提供torch、transformers/tokenizer/safetensors等本机BGE依赖。Docker构建参数 `INSTALL_LOCAL_MODELS` 默认`true`，保证默认镜像具备语义检索的依赖条件；它不携带权重，也不能代替向量发布成功验收。设为`false`可制作仅核心依赖镜像，预检会显示本地语义检索降级，不能按完整混合检索交付。

默认 `TORCH_INDEX_URL=https://download.pytorch.org/whl/cpu`，镜像先从该平台源安装requirements-models里的固定torch版本，再安装其余模型依赖，避免CPU交付误装大体积CUDA依赖。内网应替换为经批准且包含对应CPU wheel的镜像源；GPU需匹配实际平台/CUDA轮子和运行时，另行验证。如果指定版本没有对应平台wheel，构建会失败，不自动放宽版本或切换GPU包。修改build参数后须重新构建镜像，单独重启容器不安装依赖。

直接依赖版本固定不等于全部传递依赖和平台wheel已锁定。正式冻结时记录镜像digest、Python/OS包清单、两份requirements及代码哈希，并保存同一镜像用于恢复；在干净目标平台形成lock/wheel哈希集合后再承诺可重复安装。核心路径使用pypdf，不再默认安装旧Chroma/FlagEmbedding/PyMuPDF；如果另行打包legacy工具，其依赖和许可证仍需独立判断。

在配置完成的项目根执行：

```console
docker compose config --quiet
docker compose build cost
docker compose run --rm --no-deps --entrypoint python cost scripts/preflight.py --production --network --json
docker compose up -d cost
docker compose ps
docker compose logs --tail 100 cost
```

预检退出码 `0` 表示必须项通过，可降级项仍需阅读；`1` 表示必须项失败；`2` 表示命令参数错误。容器启动前会自动执行不联网的预检。首次空数据库/无模型可告警继续，用授权导入流程装入业务数据。没有本地模型时只能验收系统实际提供的词法/结构检索降级能力；不能标为向量与重排均验收通过。LLM 不配置或未批准外发时，保持明确降级，不能宣称完整 AI 流程已经成功。

需要模型时，准备通过来源与许可核查、已完整下载的目录：

```text
模型根/
  bge-m3/config.json + 权重/tokenizer等
  bge-reranker-v2-m3/config.json + 权重/tokenizer等
```

填写 `COST_MODELS_HOST_DIR` 并使用：

```console
docker compose -f compose.yaml -f deploy/compose.models.yaml config --quiet
docker compose -f compose.yaml -f deploy/compose.models.yaml up -d cost
```

这些命令不下载模型。模型大小、上下文、并发和 CPU/GPU 内存需求以目标硬件实测为准，默认 `8g/2 CPU` 只是资源上限示例。当前文件提供 CPU 部署，不含已验证 GPU 运行时。报告中文字体也需在目标镜像里生成样本人工检查。

宿主仅开放回环 `127.0.0.1:8501` 与 `127.0.0.1:8000`，由既有 HTTPS 代理转发 UI；参照 `deploy/nginx.conf.example` 接入已有证书流程。必须测试 WebSocket、上传、登录回调、下载与 token 失效。API 默认仅留宿主回环，外部集成暴露须同时配置 Bearer 客户端、限流与 CORS。不要关闭 XSRF/CORS 来绕过部署问题。

容器健康检查只访问本容器UI/API的健康路由，不调用模型、读取报表或发送任务。healthy只表示进程响应，不能代表登录、数据、检索和派发链全部健康。入口同时启动API、UI和`python scripts/run_task_worker.py`；任一子进程退出会停止整个实例并清理其余进程，再由Compose重启。worker只处理已批准且明确下发的任务，恢复门禁仍阻断POST，允许GET回执核对。

当前worker适配的是官方mock，目标仅允许`127.0.0.1:8090/localhost:8090/[::1]:8090`。容器回环不是宿主回环；本Compose不启动、不分发官方mock。容器端到端任务验收需由运维将已授权mock安排在相同网络命名空间的8090回环端口，不能通过改为`host.docker.internal`绕过目的地策略；未准备mock时不得把派发链标为可用。真实企业RPA仍需独立接入授权与契约验收。

## 4. 预检、监控与日志

裸 Python 环境将环境变量导出后执行（Python CLI 不自动读取 dotenv）：

```console
python scripts/preflight.py --json
python scripts/preflight.py --production --network --hash --json
python scripts/backup_restore.py metrics
```

生产预检分类如下：

| 分类 | 必须/可降级 | 当前检查 |
|---|---|---|
| Python、Web/API、表格、pypdf/ReportLab、Authlib/PyJWT/crypto等核心依赖 | 必须 | 对齐requirements.txt，读取模块/分发版本，不导入大模型 |
| OIDC授权映射、auth secrets | 企业必须 | HTTPS结构、映射schema、回调、cookie secret；不输出值 |
| 任务worker服务主体 | 企业必须 | COST_WORKER_SUBJECT映射存在且启用，具备task.send和非空工厂/产品scope；不输出主体值 |
| 数据根/managed父目录、路径分离、空间 | 必须 | 访问权限、至少默认1 GiB空闲（可用参数调整） |
| managed SQLite、登记原件与hash | 必须 | quick_check/foreign_key_check；`--hash`核对原件/快照/发布manifest；不把已弃用legacy kb/chroma_db作为启动必须项 |
| 维护标记 | 必须处理 | 存在时拒绝启动和写入 |
| 模型依赖、权重、内存余量、业务数据是否初始化 | 可降级 | 对齐requirements-models.txt，检查目录与权重结构、系统/cgroup可用内存；不试加载 |
| 恢复任务核对门禁 | 允许只读/核对 | 阻断派发，直到复核完成 |
| OIDC连通、模型完整hash | 需目标验收 | 分别显式 `--network`、`COST_MODEL_MANIFEST` + `--hash` |

模型 manifest 的格式为 `{"files":[{"path":"相对manifest父目录的模型文件","sha256":"64位哈希"}]}`，由可信模型交付渠道生成并保留来源；预检拒绝路径越界。`deploy/generate_inventory.py --model-root` 的 `models[].files` 可在交付时单独导出为这个结构。哈希证明相同字节，不证明模型许可、无漏洞或正确率。

`operations_metrics()` 和 `backup_restore.py metrics` 输出时间、磁盘总/剩余字节、managed/SQLite/WAL字节、数据库数、维护与恢复标记、outbox各状态数量，不输出工厂产品、正文、人员、令牌。监控命令只给系统运维账户或已有受保护采集器使用，不新增无认证监控端口。

| 监控对象 | 告警与处置 |
|---|---|
| 健康路由失联、容器持续重启 | 查看受限日志和必须项预检；避免重启风暴掩盖权限/磁盘错误 |
| 磁盘剩余、WAL持续增长 | 在业务容量阈值前告警；核查长事务与未结束读连接，按停写流程处理，不能手删WAL |
| 备份作业退出码、最后成功时间、独立恢复结果 | 任一失败保留上一份有效归档并告警；不得把产生ZIP当成备份成功 |
| outbox unknown/leased/retry积压 | 先查远端回执、租约与错误；不得换新task_id无条件重发 |
| 维护/恢复门禁持续存在 | 向维护责任人核对工单；不能以删除文件代替核查 |
| OIDC错误率、证书/客户端secret有效期 | 按企业到期窗口告警，演练轮换及退出/重新登录 |
| 请求/排队/检索/模型/渲染耗时与降级率 | 接入现有应用指标，在目标场景记录p50/p95和失败类别；当前CLI未实现全链路直方图 |

`enterprise.operations.log_operation(event, **fields)` 提供结构化运维事件，递归遮蔽 token/password/api_key/cookie/prompt/content/payload/email 等字段及常见字符串凭据；调用方只传固定事件名、request_id/job_id/analysis_run_id、耗时、结果码和计数。它是辅助防线，不能把原始请求体、SQL参数、完整异常、提示词、模型响应或数据明细送入普通日志后再指望正则完全清除。容器关闭 Uvicorn access log，Streamlit 日志为 warning；代理样例 access log 不写查询串，防止 OIDC code 泄露。检查企业日志采集器也遵守这些规则。

业务审计保留操作者稳定ID、前后值/原件与回执是追溯要求，由授权访问和留存制度管理，不套用普通运维日志的删值规则。Compose 每容器日志轮转 `10m × 5` 是容量示例；留存期限按记录类别及企业制度批准，不宣称统一法规期限。

## 5. 一致备份协议与命令

备份必须先停止 UI/API、任务worker、知识上传/索引构建、legacy ingest/watch 和任何外部写文件脚本。文件锁只约束遵守协议的进程，命令中的 `--writers-stopped` 是运维人员的停写声明，工具不能自行证明主机不存在未接锁的进程。

所有受控变更使用同一 `COST_MANAGED_DIR/.operations.lock`：

```python
from enterprise.operations import guarded_write, write_guard

# 自动选择self.root；函数没有self.root时使用paths.MANAGED_DIR。
@guarded_write
def publish(self, ...):
    # 整个DB + blob + manifest + active pointer操作都在锁内。
    ...

with write_guard(root):
    ...
```

锁使用 POSIX flock 或 Windows msvcrt，支持线程/调用嵌套重入，不是分布式锁。备份持排他锁并写 `.maintenance.json`，写入入口遇持久维护标记拒绝。备份异常正常退出会释放标记；进程被强杀可能遗留标记，须确认所有写进程停止并调查后手动清除。**不要删除 `.operations.lock` 文件**，删除会使活跃进程与新进程锁住不同 inode。

备份包含：managed 全树中的业务库、SQLite内嵌成本原件/审计、知识 `blobs`、知识发布库与每次 `knowledge_releases` 的索引/manifest、报告与任务记录；data 根的 CSV/XLS(X)/PDF/DOC(X)/TXT/JSON/SQLite 业务文件，以及 `kb/data_upload/docs_upload/outputs/artifacts/report_templates/templates/releases/index_releases` 全树。未知业务子目录需先迁入该合同范围；**不静默假设任意目录都已备份**。

排除代码、`.git/.venv/__pycache__/.pytest_cache/.local/.streamlit/secrets/models/logs/backups`、环境文件、常见秘密文件与 `COST_AUTHORIZATION_FILE/COST_LLM_CONFIG_FILE/COST_STREAMLIT_SECRETS` 指定文件。业务数据库和原件中可能含敏感成本/人员/模型运行内容，这些是业务备份的必要记录，不能因日志脱敏规则而删除；归档必须按同等级访问控制。秘密文件不要以无法识别的任意名字混放业务数据树。

可变 SQLite 使用 `Connection.backup()`，包括已提交 WAL，不直接复制正在使用的主库。已发布不可变索引由 `knowledge_releases.db.releases` 的 canonical `manifest` 与 `manifest_sha256` 绑定原始字节：验证该数据库记录、索引原hash、数据库完整性且无非空WAL/journal后原样复制，避免SQLite备份改变文件页头导致发布hash失效。发布清单不依赖索引旁侧的 `manifest.json`；归档自己的顶层manifest是另一种备份清单。未提交事务不备份，未完成索引不作为成功发布。WAL/SHM不单独拼入恢复目录。

归档内 `manifest.json` 记录 backup_id、起止时间、一致性方式、每文件相对路径/大小/SHA256/mtime/类型，保留 legacy 数据文件mtime排序。另生成 `归档.zip.sha256`，在不同受控位置保留该摘要。哈希只能发现损坏/不一致，不能防止同时拥有归档和摘要的管理员重写，也不是电子签名。

裸 Python 停写后：

```console
python scripts/backup_restore.py --data-root "/业务data根" --managed-root "/业务managed根" backup --writers-stopped --output "/独立备份目录/2026-09-18.zip"
python scripts/backup_restore.py verify --archive "/独立备份目录/2026-09-18.zip"
```

输出父目录必须已存在且文件名未占用。通常使用两个数据根之外的独立备份存储；本地演练允许唯一的内部例外 `COST_DATA_DIR/backups/` 下的文件及子目录，例如数据根仍为项目根时的 `backups/local-2026-09-18.zip`。该目录在数据输入与递归扫描中始终排除，连续备份不会把旧ZIP、摘要或临时归档再次打包。数据根内其他目标、相似名称 `backups-other/`、`backups`目录本身、自定义 `COST_MANAGED_DIR` 内的任何目标仍被拒绝；目标路径中的符号链接和Windows junction也被拒绝，不能借链接改变此边界。

本地副本只便于演练与暂存，**不能替代独立介质或异地备份**：同一磁盘故障、主机失窃或破坏可能同时损失生产与副本。工具写临时归档、验证后才发布目标；预留归档暂存与SQLite快照空间，峰值按实测并留余量。输出 ZIP **不加密**，应写入企业批准的加密文件系统/备份平台，异地复制、密钥托管与保留策略由运维承担。

Compose 示例（`/宿主备份目录` 需预创建且 UID 10001 可写）：

```console
docker compose stop cost
docker compose run --rm --no-deps --entrypoint python --volume "/宿主备份目录:/backup" cost scripts/backup_restore.py backup --writers-stopped --output /backup/2026-09-18.zip
docker compose run --rm --no-deps --entrypoint python --volume "/宿主备份目录:/backup:ro" cost scripts/backup_restore.py verify --archive /backup/2026-09-18.zip
docker compose up -d cost
```

有可选模型覆盖时，所有 Compose 命令使用同一组 `-f` 参数。停止/备份失败后先处理原因，不能机械执行最后一行假装维护成功。不以 `down -v` 停服，该命令会删除卷。

维护进程异常退出后，确认停止所有写者再执行：

```console
python scripts/backup_restore.py --managed-root "/业务managed根" maintenance-clear --writers-stopped
```

## 6. 恢复、核对与切换

恢复只接受新目录或空目录，不覆盖生产根。工具验证整包路径、重复/大小写冲突、逐文件hash、SQLite与登记原件，再向同级临时目录展开，成功后重命名为目标。拒绝绝对路径、`..`、Windows盘符/反斜杠、特殊设备文件/软链接和未登记条目；默认解压总量上限50 GiB，可经容量批准调整 `--max-unpacked-gib`。

```console
python scripts/backup_restore.py restore --archive "/备份目录/2026-09-18.zip" --target "/恢复父目录/rehearsal-2026-09-18"
python scripts/preflight.py --data-root "/恢复父目录/rehearsal-2026-09-18/data" --managed-root "/恢复父目录/rehearsal-2026-09-18/managed" --hash --json
```

恢复父目录应已存在。目标生成 `data/`、`managed/`、`restore_manifest.json` 与 `restore_report.json`。权限策略、OIDC secrets、LLM凭据从独立托管恢复；默认不会从业务归档恢复旧权限而重新授权已离职账户。模型/镜像使用对应冻结版本并核对hash。

容器隔离恢复示例：

```console
docker compose run --rm --no-deps --entrypoint python --volume "/宿主备份目录:/backup:ro" --volume "/宿主恢复父目录:/recovery" cost scripts/backup_restore.py restore --archive /backup/2026-09-18.zip --target /recovery/rehearsal-2026-09-18
```

此命令只写新恢复根，不把恢复结果覆盖到原卷。切换前按业务负责人见证清单核对：成本当前修订/期间、source_files与知识blob、快照历史回看、知识 active release/manifest/原件、报告DOCX/PDF与引用、权限拒绝、任务批准版本与远端回执。读取快照不重新调用模型；模型重跑是新运行。

恢复始终生成 `managed/.restore-review-required.json`，报告所有派发被阻断，并统计 known outbox 状态。`blocked/pending/retry/unknown/leased` 均进入需要核对的清单；保留原状态枚举与批准内容，不往 CHECK 约束写入不存在的 `needs_review`。任务 `dispatch()` 先调用 `assert_dispatch_allowed()`，阻断新外发；`sync()` 只 GET，可以用于逐项核对。`delivered` 仅表示 RPA 服务受理，不能等同实际消息送达或整改完成。

先按稳定 task_id 查远端存在性与批准内容。超时/旧备份期间远端已创建的任务，必须更新回执，不能改新ID重发。远端不可查、内容冲突、mock重启丢失记录的任务继续保持人工核对。完成所有待办后由有权限的负责人记录工单，再停止写进程并执行：

```console
python scripts/backup_restore.py --managed-root "/恢复父目录/rehearsal-2026-09-18/managed" review-complete --writers-stopped --actor "实际运维主体ID" --note "回执核对工单编号及范围"
```

该命令保留 `managed/restore_reviews/` 复核记录并清除全局门禁，**不发任务、不改任务状态、不代替重新批准/下发操作**。仅删除门禁文件会绕过复核记录，禁止作为正常恢复步骤。

生产切换：停止旧实例，保留旧卷；设置 `COST_RESTORE_HOST_ROOT` 为新根绝对宿主路径，验证 UID 10001 权限，执行：

```console
docker compose -f compose.yaml -f deploy/compose.restore.example.yaml config --quiet
docker compose -f compose.yaml -f deploy/compose.restore.example.yaml up -d cost
```

如使用模型卷，同样追加该覆盖文件。先验证只读和登录再开放写入。回退必须停止新实例、保留新期间写入证据、核对外部任务，再恢复旧镜像及原数据根；若新版本有不兼容 schema，不允许仅降级代码后继续读写升级过的库。升级前另做停写备份，向新根恢复演练后验收。

RPO/RTO由业务批准并通过目标数据量、机器、模型、外部依赖实测确定，本文不预设15分钟/1小时SLA。记录备份时点、最近已批准业务时点、恢复耗时、核对耗时、可恢复外发状态和演练签字。

## 7. 交付清单与责任

生成环境组件清单（新输出文件，不覆盖旧清单）：

```console
python deploy/generate_inventory.py --output "/交付目录/component-inventory.json" --source-revision "冻结的提交或交付版本号" --model-root "/批准的模型根"
```

不带模型时省略 `--model-root`。脚本列实际安装 Python 包的来源/版本/许可证metadata，计算允许的代码/资源与模型文件hash，不读取业务数据和密钥。它不是完整 SPDX/CycloneDX SBOM，不扫描漏洞，不替代许可证兼容性、商业授权、模型数据范围与重分发判断。另归档镜像摘要、OS包清单及版权文件、模型上游精确revision和授权记录、字体/ECharts等notice、依赖wheel来源与hash。不能将主机混装环境的清单伪称为干净生产镜像清单。

| 责任 | 最少交接内容 |
|---|---|
| 业务负责人 | 用途/期间/金额口径、导入/批准责任、源资料授权、RPO/RTO、恢复核对人员 |
| 身份管理员 | IdP client/issuer/audience、主体映射、撤权、secret轮换与紧急收回 |
| 运维负责人 | 镜像digest、卷位置/权限、HTTPS证书、备份调度告警、恢复演练、容量与升级回退 |
| 模型/数据管理员 | 模型来源/许可/hash、外发批准范围、知识release与撤销、降级验收 |
| 交付负责人 | 测试结果与缺口、完整组件清单、许可裁决、培训/验收记录和后续支持边界 |

正式验收至少覆盖：空环境安装、真实IdP最小授权、未经授权401/403、撤权生效、中文DOCX/PDF、无模型/模型超时降级、隔离备份恢复、旧备份外发去重、磁盘满/写失败、证书与密钥轮换。本文提供实现和执行步骤，尚未执行的现场检查需保持“待验收”。
