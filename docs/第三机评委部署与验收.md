# 第三机评委部署与验收

更新：2026-09-23。面向获授权评委电脑/受控评审环境，不能将源码ZIP解释为含赛题数据、模型、密钥和全部现场验收的完整安装包。本文命令是待目标机执行的操作指南；本轮只运行只读文件/版本预检与静态测试，**没有安装依赖、构建Docker镜像、执行真实第三机部署、模型调用或RPA发送**。

## 1. 技术链和分包

| 层 | 当前技术 | 跨机准备与边界 |
|---|---|---|
| Web/API | Streamlit、FastAPI/Uvicorn，Python 3.12 | 本机评审用回环local身份；企业容器强制OIDC，不以共享默认密码替代 |
| 成本 | pandas + 受控SQLite修订、Decimal核验 | 8张成本CSV；按工厂/产品/规格/月预览→授权确认，既有受控修订优先于文件 |
| 知识 | pypdf/python-docx/文本；版本SQLite；LangChain BaseRetriever | 7份PDF+2份参考CSV，另可登记DOCX/TXT；只有确认并发布后进入检索 |
| 检索 | 本地BGE-M3 dense + BM25 + 文本证据图 + 受控规则重排 | torch/transformers只加载本地权重；正式模式需要向量发布与当前进程就绪。当前规则重排不是BGE reranker神经推理 |
| 生成 | OpenAI兼容网关，例如已批准的Qwen接口 | 本地BGE不等于本地生成模型；cloud Qwen会发送经选取的分析/知识内容，须事先获批准。无批准则不调用；可另配获准本地兼容LLM |
| 导出 | python-docx、ReportLab、matplotlib，ECharts看板 | 授权模板和覆盖中文/符号的字体；不是依赖安装成功就完成报告验收 |
| 任务 | 固定版本审批/签发/outbox + 官方loopback mock | 官方脚本单独提供；成功仅模拟HTTP受理，不是实际微信/企业整改完成 |

交接至少分为：

1. **源码包**：应用/测试/requirements/Dockerfile/公开无秘密配置、hash清单；不含CSV/PDF/DOCX原件、DB、模型权重、现机私有配置或秘密。
2. **赛事授权私有资料包**：10 CSV（8成本+2参考）、7 PDF、Word报告模板、官方mock及说明；原件保持不变，附来源/使用范围/sha256清单。只交给获授权人员，不进入公开仓库。
3. **模型与平台依赖介质**：用户/部署方另行提供完整BGE-M3目录、可选本地LLM、获批准的wheel/镜像/字体介质。此次本地只读检测BGE主权重2,271,145,830字节，约2.27 GB；不自动打包或上传这类大权重。
4. **目标机私有配置**：评审机现场设置密钥、OIDC、授权映射和模型endpoint，不复制开发机真实秘密。核对软件/字体/模型来源、许可证及使用/再分发范围，必要时由相应权利负责人确认；本文不提供法律意见或授权保证。

## 3. Windows本机评审：准备、启动、初始化

### 3.1 Python与依赖

在新的源码解压目录执行。已有 `.venv` 不要照搬不同电脑/平台，尤其不能把开发机venv当安装包。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links 'D:\评审依赖\win-py312-wheels' -r requirements.txt -r requirements-models.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe launch_system.py --check
```

上述是离线安装，前提是已准备匹配Windows/Python3.12/CPU平台的所有传递依赖wheel。缺轮子就停止，不自动联网补装或放宽固定版本。允许联网的软件源安装必须由部署方另行批准；本次未执行任何安装。根依赖固定不等于所有平台都已冻结可重复环境。

### 3.2 数据、模型、字体、身份路径

```powershell
$env:COST_AUTH_MODE = 'local'
$env:COST_BIND_HOST = '127.0.0.1'
$env:COST_TENANT_ID = 'default'
$env:COST_DATA_DIR = 'D:\project4-evaluator\business'
$env:COST_MANAGED_DIR = 'D:\project4-evaluator\managed'
$env:COST_LLM_CONFIG_FILE = 'D:\project4-evaluator-private\llm.json'
$env:BGE_M3_PATH = 'D:\评审模型\bge-m3'
$env:BGE_RERANKER_PATH = 'D:\评审模型\bge-reranker-v2-m3'
$env:REPORT_CJK_FONT = 'D:\评审字体\approved-cjk.ttf'
$env:COST_OFFICIAL_MOCK_SCRIPT = 'D:\评审资料\创灵境_考题模拟数据\05_RPA接口文档\mock_rpa_server.py'
$env:HF_HUB_OFFLINE = '1'
```

`BGE_RERANKER_PATH`是可选兼容资产，不是当前规则重排的必需神经模型。`paths.py`含开发机便利探测，但第三机必须显式指定路径，不能假设存在同盘符模型。模型目录需 `config.json`、tokenizer配置和词表、完整权重/分片；不只复制一个bin。COST_DATA_DIR和managed应是新、受控且可写的数据根，源码和秘密分开存放。

授权资料布局：将官方 `01_成本明细数据`的8CSV、`02_行业参考数据`的2CSV、`03_制药知识文档`的7PDF及`04_报告模板/月度成本分析报告模板.docx`，由资料负责人核对hash后复制到上述business根，保留原名；不要将官方mock/秘密夹在业务原件中。既有 `enterprise.bootstrap.official_document_specs()`要求九份知识/参考原件在source根直接可见，不递归发现官方子目录。

### 3.3 初始化知识与启动

**新评审根**可先运行显式核准初始化；其写入知识DB和索引，须已确认资料范围，不属于只读预检：

```powershell
.\.venv\Scripts\python.exe -B -Xutf8 scripts/bootstrap_system.py `
  --source "$env:COST_DATA_DIR" --root "$env:COST_MANAGED_DIR" --build-timeout 1800
```

当前bootstrap默认dense，`enterprise.bootstrap.bootstrap_knowledge()`传 `require_embeddings=True`；缺模型或向量构建失败不会以词法发布冒充正式通过。`--catalog-only`只登记不发布；`--lexical-diagnostic-only`仅明确非合规诊断，正式模型分析应拒绝，不能用它通过语义混合检索要求。CLI只适用于local模式；生产OIDC使用已认证知识管理员页面。

`--build-timeout`默认600秒，允许 `(0,3600]`。初次权重加载、全模型hash和向量化耗时取决于CPU/内存/存储；现机多分钟首次构建经验不是评审机“八分钟必过”承诺。`COST_EMBED_THREADS`范围1–64，默认4；`COST_EMBED_BATCH_SIZE`范围1–32，默认2。内存不足可在首次发布之前选择batch1并减少并行模型进程，但不要一边运行一边改参数：这些参数进入模型fingerprint，发布和查询必须一致。权重约2.27 GB不代表运行内存只需2.27 GB。不要同时多开bootstrap和应用模型副本；命令结束后再启动。

```powershell
.\.venv\Scripts\python.exe launch_system.py --no-browser --no-worker
```

评审先禁worker，避免恢复的已签发任务自动派发。启动器回环监听，输出实际UI/API端口；默认8501/8000占用时可寻找后续空端口，不应死记地址。父终端保持打开，Ctrl+C只停止本次拥有的子进程。

要进行经授权的mock验收，再显式使用 `--with-mock`；启动器以uvicorn将官方脚本限定为127.0.0.1:8090，不直接运行官方脚本的全接口main。`--no-worker`仍保留，直到任务审核/签发/发送环节明确批准。不要启动第二套现有系统覆盖旧交付。

### 3.4 模型就绪与云端配置

应用进程启动会发起非阻塞预热，bootstrap成功不代表另一个进程已预热。页面“知识检索运行状态”或当前API的 `GET /api/search/readiness`应为ready，且匹配活动发布/embedding fingerprint；GET须沿应用现有身份边界。HTTP服务健康不是检索ready。正式检索必须有完整dense发布、模型就绪及权限过滤；词法诊断不等价。

模型网关可配置 `COST_LLM_BASE_URL / COST_LLM_MODEL / COST_LLM_TIMEOUT`，密钥使用目标机私有配置或秘密注入。默认兼容Qwen不代表已批准外发；只有在接口与分析数据使用获得批准后设置 `COST_LLM_APPROVED_CLOUD=true`。不要把API key写进本指南、命令历史、聊天、公开包、CSV或日志。使用设置页面/受控秘密管理在目标机现场配置。真正全离线需另有本地OpenAI兼容生成模型；仅BGE+未配置LLM只能检索/确定性分析，不是完整AI生成。

## 4. Docker：准确能力与待验收范围

当前Dockerfile基于Python3.12 Debian bookworm，默认 `INSTALL_LOCAL_MODELS=true`安装本地模型依赖，不带权重；镜像构建本身要获取基础镜像、apt/pip及固定字体资源，严格离线现场需提前批准并构建/导入镜像，不能把HF离线环境变量当“Docker build无需网络”。本次未执行Docker构建。

本次最小修复：明确COPY `config/domain_profiles/pharma.json`与4个未激活制造业适配JSON；`.dockerignore`只添加这5个无秘密文件及bootstrap/evaluator-preflight/human-validator脚本，未开放任意客户config。静态测试通过不等于镜像构建或容器业务已通过。

容器入口 `deploy/entrypoint.py`强制OIDC；**不支持把生产Compose改local来逃过登录**。先按 `docs/部署与运维手册.md`设置私有OIDC/授权映射、worker subject、宿主只读秘密路径与既有HTTPS代理。`.env.example`只是空结构，禁止提交实际 `.env`。模型宿主根布局应为 `bge-m3/`和可选`bge-reranker-v2-m3/`，设置 `COST_MODELS_HOST_DIR`。

```powershell
docker compose -f compose.yaml -f deploy/compose.models.yaml config --quiet
docker compose -f compose.yaml -f deploy/compose.models.yaml build cost
docker compose -f compose.yaml -f deploy/compose.models.yaml run --rm --no-deps --entrypoint python cost scripts/preflight.py --production --json
docker compose -f compose.yaml -f deploy/compose.models.yaml up -d cost
docker compose -f compose.yaml -f deploy/compose.models.yaml ps
```

这些命令仅在获得部署操作许可、数据准备、OIDC/worker配置后执行，本轮未执行。生产入口会启动worker，故只在新空受控根或已核对的恢复状态使用；不要把local评审的“先不派发”要求直接套到默认容器入口。

授权business文件须由运维导入持久卷 `/var/lib/project4/data`，保证UID10001可读写；不能COPY进公开镜像。私有LLM配置卷为 `/var/lib/project4-private`。通过知识UI核准/发布，不在OIDC容器执行local-only bootstrap CLI。Compose默认8g/2CPU只是资源限制示例，不是BGE加载/并发SLA；须实测峰值和预留余量。

官方mock未随Compose启动/分发；宿主localhost不是容器localhost。默认RPA目的地是受限loopback，需经批准在同网络命名空间准备mock，或单独完成受控适配验收，不能通过改任意公网地址绕过策略。真实RPA/微信仍不在该mock验收范围。

## 5. 评委验收顺序与必须保存的证据

1. **资料真实性与场景**：确认10CSV/7PDF/模板/mock来源和hash；确认评委给定的三个产品/规格/期间/主题。未取得正式指定时明确写项目自选，不假造指定名单。
2. **数据确认**：月度数据管理预览多文件、数值闭合、scope、历史期间；授权主管确认。新产品还须受控配置类别/包装/材料，不仅上传名称。保留成本revision/hash；全量CSV目前为upsert，不自动删除缺失行。
3. **知识确认及dense发布**：预览PDF/DOCX/TXT/CSV、图片/OCR覆盖提示；确认范围/生效期/证据角色；发布并记录release ID、chunk/vector count、embedding及domain_graph版本/hash。扫描空文本必须拒绝；不能借预览成功宣称完成OCR。
4. **readiness**：确认实际评审应用进程ready，不只检查文件在磁盘或API存活。记录实际混合检索支路，失败和超时保留。
5. **M1/M2/M3**：按三场景生成报告/单品归因/三步对标；保存DOCX/PDF、结构分母/通过数、确定性数值误差、来源引用、model实际返回和采用/拒绝/降级回执。配置模型名不等于模型实际运行；规则降级不能记作AI成功。
6. **模拟RPA三个任务**：经显式授权和人工审核，关联场景、形成草稿→提交→批准→签发→发送；保存POST受理与GET状态、原task_id、分母/成功数。普通mock任务只会自动received；completed需要官方特定模拟路径，不能改状态造成功。HTTP200成功触发不等于真实微信或业务闭环。
7. **真人0–5**：将实际场景身份/report_id绑定 `human_scores.csv`，未评分的两分值、reviewer、时间、comments留空；禁止AI填写或以0占位。用 `python scripts/validate_human_scores.py --assessment '获授权评测目录/assessment.json'`校验同目录评分CSV；真人完成后加 `--require-complete`（有效但未完成人评退出2），未完成用pending，不发布平均分。不要复用旧批次评分去覆盖新报告。
8. **最终矩阵**：四项并列：结构完整度、真人归因合理性、RPA触发成功率、三步格式正确率；另列差异误差≤1%、退化状态、代码/配置/数据/模板/发布hash。未做的写未测，不以几十/上千个合成测试代替业务验收。
